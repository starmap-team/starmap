# 数据流水线 P0 问题记录 & 修复计划

## 问题记录

### P0-1: Celery event loop 错误 — 流水线完全不可用

| 字段 | 值 |
|------|-----|
| **状态** | 🔴 Open |
| **严重度** | P0 (Blocker) |
| **复现** | 触发任意流水线 → crawl 阶段 0 记录 → 后续阶段永远 pending |
| **根因** | Celery 是 sync Worker，调用 `asyncio.run()` 创建新 event loop。SQLAlchemy async engine pool 绑定到原始 event loop，导致 DB 操作 `RuntimeError: Task got Future attached to a different loop` |
| **影响** | `_publish_stage_progress` SSE 广播失败、`_mark_stage_completed` DB 更新失败、`advance_pipeline` 永远不触发 |
| **证明** | `docker logs starmap-celery-worker` 满屏 RuntimeError |

### P0-2: jd_raw 表不存在 — 爬虫数据无存储

| 字段 | 值 |
|------|-----|
| **状态** | 🔴 Open |
| **严重度** | P0 (Blocker) |
| **复现** | `docker exec starmap-postgres psql -U starmap -d starmap -c "SELECT COUNT(*) FROM jd_raw"` → `ERROR: relation does not exist` |
| **根因** | crawler/persistence/dao.py 使用独立的 SQLite engine (`crawler.persistence.database.engine`)，不与 PostgreSQL 共享 |
| **影响** | 爬虫即使成功采集，数据也写入 `crawler/crawler.db` SQLite，Pipeline 使用的 PostgreSQL 没有数据 |

### P0-3: 知识图谱从未由流水线构建

| 字段 | 值 |
|------|-----|
| **状态** | 🔴 Open |
| **严重度** | P0 (Blocker) |
| **复现** | Neo4j 317 个 Skill 节点全部是历史数据，graph_sync 阶段从未在 Pipeline 中执行 |
| **根因** | 依赖 P0-1 修复，graph_sync 阶段需要 crawl/import 先完成 |
| **影响** | 流水线无法产生图谱数据，整个闭环断裂 |

## 修复计划

### Fix #1: Celery event loop

**方案**: 在 Celery 任务 (`celery_app.py` `execute_pipeline_stage`) 中，将整个阶段执行包装在单个 `asyncio.run()` 调用中
**涉及文件**: `backend/app/tasks/celery_app.py`
**改动范围**: ~20 行
**风险**: 低 — 只改动 Celery 任务入口，不影响 API 层

### Fix #2: jd_raw 表

**方案**: 
1. 在 crawler DAO 初始化时自动创建 jd_raw 表到 starmap PostgreSQL
2. 或者：将 crawler 的 persistence 引擎指向 starmap PostgreSQL
**涉及文件**: `crawler/persistence/database.py`, `crawler/persistence/dao.py`
**改动范围**: ~10 行
**风险**: 低 — 新表，不影响现有数据

### 校验方案

1. 触发 incremental pipeline (仅 crawl) → 验证 stage 有 records
2. 检查 PostgreSQL jd_raw 有新行
3. 触发 full pipeline → 验证 graph_sync 完成
4. 检查 Neo4j 有新节点
