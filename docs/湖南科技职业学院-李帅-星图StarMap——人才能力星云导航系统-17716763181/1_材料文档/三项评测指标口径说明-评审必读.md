## 二、F1 是什么？为什么我们用它而不是"准确率"？（评委最可能的追问）

### 2.1 一句话解释
**F1 是"精确率(P) 与 召回率(R) 的调和平均"**——它同时惩罚"多提取了错误技能"和"漏掉了真实技能"，
比单纯"准确率"（只问"答对多少"）更严苛、更能反映抽取质量。

### 2.2 三个指标的数学定义（本项目的"分子分母"）

| 指标 | 定义（本项目实际口径） | 含义 |
|------|----------------------|------|
| **精确率 Precision (P)** | 抽取出的技能中，**真实正确**的比例 | "我们提取的每 100 个技能里，有多少真是岗位要求的？" |
| **召回率 Recall (R)** | 真实需要的技能中，**被我们抓到**的比例 | "岗位真实要求的每 100 个技能里，我们抓对了多少？" |
| **F1 分数** | 2×P×R / (P+R) | 精确率与召回率的平衡点 |
| **准确率 (Accuracy)** | 判定正确的总数 / 总样本数 | 匹配场景：判断"该岗位是否匹配"的方向是否正确 |

### 2.3 为什么"F1≥90%" 比 "准确率≥90%" 更严格（诚实且有利的论证）

- **准确率(粗口径)**：只要"答对"就算对，不关心**漏了多少**、**多提了多少**——很容易被"保守抽取"(少提取)刷高。
- **F1**：同时卡住两个维度——漏提取(R 低)或多提取(P 低)都会被大幅拉低。
  - 例：模型只提取 1 个技能且正确 → 精确率 100%，但召回率 2%(漏了 49 个) → **F1≈0.04**，远低于 90%。
- **结论**：本项目 F1=0.9622，意味着**在"不能少提、不能多提"双重约束下仍达到 96%+**——这比字面"准确率≥90%"的达成难度更高。**我们提交的是更严格的指标，而非放宽。**

### 2.4 项目门禁如何执行这个口径（可复现）

- `evaluation/accuracy_gate.py`（CI 门禁 + 定时）：
  - JD 解析 → 读 `Avg F1`（run_real_eval.py，真实 LLM 110 样本，**非**关键词 baseline）
  - 简历提取 → 读 `F1=`（run_resume_eval.py，真实 LLM 25 样本）
  - 人岗匹配 → 读 `准确率`（run_match_baseline.py，10+ 抽样，区间+方向判定）
  - 任一 < 0.90 → 门禁 exit 1 失败；全部 ≥90% → CI 通过（历史流水线见 CI 全绿记录）。
- **评审可复现**：`python evaluation/accuracy_gate.py` 一键验证。

## 三、为什么不用"关键词匹配"的粗准确率（对比说明，避免误读高数字）

| 对比项 | 关键词 baseline（初版） | 本项目最终（LLM 语义抽取） |
|--------|----------------------|--------------------------|
| JD 解析 | F1≈0.78（不过线） | **F1=0.9622**（真实 LLM qwen-plus） |
| 简历提取 | F1≈0.78 | **F1=0.9158**（真实 LLM，走线上 `/resume/upload` 同管线） |
| 人岗匹配 | 关键词命中率低 | **97.45%**（区间+方向判定，golden 432 样本） |

> 说明：本项目是**真实 LLM 语义提取**而非关键词命中，指标更高且更可信；
> 早期关键词 baseline 曾统计为 0.7569（讯飞 key 失效的假失败），重配后恢复 0.9+——
> 这一"可诊断、可复现"的演进过程，恰恰说明评测体系可靠（非刷分）。
