# 脚本工具规范文档

## 1. 模块概述

### 职责定位
`scripts/` 目录是 StarMap 项目的运维工具箱，包含数据初始化、图谱构建、质量评估、数据种子、系统运维等 34 个脚本。这些脚本支撑从开发环境搭建到生产数据维护的全生命周期操作。

### 核心目标
1. **图谱初始化**：Neo4j schema、约束、索引、种子数据
2. **数据种子**：JD 数据、演示数据、演化快照、硬编码画像
3. **评估测量**：质量报告、Pipeline 准确率、性能测量
4. **抽取扩展**：批量 JD 抽取、图谱数据扩展、Golden Set 扩展
5. **LLM 测试**：本地 Ollama 模型测试
6. **系统运维**：日常集成、服务器维护、编码修复
7. **契约校验**：OpenAPI 契约同步检查、类型同步检查

### 在系统中的位置
```
┌─────────────────────────────────────────┐
│           scripts/ 工具箱                │
├─────────────────────────────────────────┤
│  Neo4j/图谱初始化 (8)                   │

```

## 5. 编码规范（本模块特有）

### 5.1 Python 脚本规范
- **使用 `asyncio`**：涉及 IO 的脚本使用异步（`init_neo4j_schema.py`, `seed_jd_data.py`）
- **使用 `loguru` 替代 `print`**：生产级日志记录
- **使用 `pathlib.Path`**：路径处理统一使用 `Path`
- **使用 `argparse`**：CLI 参数解析
- **ARCHIVE 标记**：废弃脚本在 docstring 中标注 `ARCHIVE:`

### 5.2 Shell 脚本规范
- **Shebang**：`#!/bin/bash` 或 `#!/usr/bin/env bash`
- **严格模式**：`set -euo pipefail`
- **UTF-8 编码**：`export LANG=C.UTF-8`
- **错误处理**：每个命令检查 exit code

### 5.3 JS/TS 脚本规范
- **使用 `ts-node`**：直接运行 TypeScript
- **类型安全**：所有脚本使用 TypeScript 编写
- **契约校验**：`check-contract-sync.js` 和 `check-type-sync.ts` 保持与 CI 一致

### 5.4 反模式
- **不要在脚本中硬编码密码**：使用环境变量或 `.env` 文件
- **不要在脚本中直接修改生产数据**：评估类脚本只读，修改类脚本需备份
- **不要使用相对路径执行**：使用 `Path(__file__).resolve().parent` 定位
- **不要忽略异常**：所有异步操作需 `try/except` 包裹
- **不要在 seed 脚本中重复插入**：检查已有数据后跳过（`seed_jd_data.py` 已实现）

### 5.5 质量报告规范
```python
# quality_report.py 的核心约定
# 评估指标：
#   - JD 解析准确率：>= 90%
#   - 简历提取准确率：>= 90%
#   - 人岗匹配准确率：>= 90%
# 预警级别：green / yellow / orange / red
# CI 模式：任何指标失败 exit 1
```

## 6. 测试规范

### 6.1 脚本自身测试
- Python 脚本需通过 `python -m py_compile` 编译检查
- Shell 脚本需通过 `shellcheck` 静态检查
- JS/TS 脚本需通过 `tsc --noEmit` 类型检查

### 6.2 集成验证
- `init_neo4j_schema.py`：验证 Neo4j 约束和索引创建成功
- `seed_jd_data.py`：验证数据插入后查询返回正确数量
- `quality_report.py`：验证 Golden Set 存在时输出正确格式
- `check-contract-sync.js`：验证与 CI 契约校验结果一致

### 6.3 Mock 策略
- 外部 API 调用使用 mock（LLM 测试）
- 数据库连接使用真实连接（本地开发环境）
- 文件操作使用临时目录（测试时）

### 6.4 测试矩阵

| 脚本类型 | 编译检查 | 单元测试 | 集成测试 | 手动验证 |
|---------|---------|---------|---------|---------|
| Python | py_compile | pytest | 真实 DB | 是 |
| Shell | shellcheck | - | - | 是 |
| JS/TS | tsc --noEmit | - | 真实 API | 是 |

## 7. 变更管理

### 修改脚本时的检查清单

- [ ] 新增脚本是否添加到 `scripts/README.md`？
- [ ] 修改 seed 脚本是否验证幂等性（重复运行不报错）？
- [ ] 修改评估脚本是否更新 Golden Set 路径？
- [ ] 新增 CLI 参数是否更新帮助文档？
- [ ] 修改环境变量是否同步更新 `.env.example`？
- [ ] 废弃脚本是否标注 `ARCHIVE:` 并说明替代方案？
- [ ] 修改 Neo4j schema 是否验证向后兼容？
- [ ] 新增数据导入是否验证数据格式和编码？
- [ ] 修改质量报告指标是否更新目标阈值？

### 契约影响
- **修改 `init_neo4j_schema.py`**：影响所有环境的 Neo4j 初始化
- **修改 `quality_report.py`**：影响 CI 质量门禁和演示就绪判断
- **修改契约校验脚本**：影响 CI 契约校验阶段
- **修改 seed 脚本**：影响开发和演示环境的数据状态

### 迁移要求
- 新增脚本需通过 `python -m py_compile` 或 `tsc --noEmit` 验证
- 修改 schema 初始化需在新环境重新执行
- 修改 seed 数据需考虑已有数据的处理策略（跳过/覆盖/追加）
- 新增评估指标需在 `quality_report.py` 中注册并设置目标阈值
- Shell 脚本变更需在 Linux 环境验证（避免 Windows 特有语法）
