# 评估套件规范文档

## 1. 模块概述

**职责定位**：StarMap 系统的质量评估体系，通过三层评估（Baseline/Sim/Real）确保技能抽取、岗位匹配等核心功能的准确性和可靠性。

**核心目标**：
- 建立基线评估（Baseline）：基于规则的关键词匹配，F1 = 0.758
- 建立模拟评估（Sim）：控制噪声的 LLM 模拟，F1 = 0.9759
- 建立真实评估（Real）：调用真实 MiMo API 的端到端评估
- 维护 4 种黄金集（Golden Set），覆盖不同业务场景
- 质量门禁：F1 >= 0.90

**在系统中的位置**：
- 上游：`starmap-contracts/openapi.yaml`（数据格式契约）、`backend/`（后端服务）
- 下游：`crawler/`（数据输出格式验证）、`frontend/`（结果展示）
- 依赖：MiMo API、Qwen API、Xunfei Spark API

## 5. 编码规范（本模块特有）

### 5.1 黄金集格式
- 使用 JSONL 格式（每行一个 JSON 对象）
- 每条记录必须包含 `id` 和 `job_title`
- 技能列表使用 `required_skills` 和 `bonus_skills` 区分
- 经验年数使用 `experience_years`（整数或 null）
- 学历使用 `education`（字符串或 null）

### 5.2 评估脚本约定
- 评估脚本应支持命令行参数（`--quick` 快速模式、`--score-only` 仅评分）
- 系统输出使用 JSONL 格式，与黄金集格式一致
- 支持增量保存和断点续跑（`system_path.exists()` 检查）
- 错误处理：异常捕获后记录到 `failures` 列表，继续处理其他样本

### 5.3 错误分析约定
- 三类错误：幻觉（false positive）、漏抽（false negative）、误分类（required/bonus）
- 生成 `error_analysis.md`，包含按类型统计和最差样本 Top 5
- 元数据文件 `evaluation_meta.json` 记录 API 版本、模型、配置等

### 5.4 质量门禁
- 基线评估：F1 >= 0.70（当前 0.758）
- 模拟评估：F1 >= 0.90（当前 0.9759）
- 真实评估：F1 >= 0.80（目标）
- 质量门禁：F1 >= 0.90

### 5.5 反模式
- **禁止**在评估脚本中硬编码 API 密钥（应使用环境变量）
- **禁止**修改黄金集数据（黄金集是只读的评估基准）
- **禁止**在评估过程中使用黄金集的标注信息（anti-cheat）
- **禁止**忽略评估失败（应记录到 `failures` 列表）

## 6. 测试规范

| 测试文件 | 覆盖范围 | 策略 |
|---------|---------|------|
| `evaluation/judge_eval.py` | F1 计算、报告生成、质量门禁 | 纯函数测试 |
| `evaluation/run_baseline.py` | 基线评估完整流程 | mock golden set |
| `evaluation/simulate_llm_eval.py` | 模拟评估完整流程 | mock golden set |
| `evaluation/run_real_eval.py` | 真实评估（需 API 密钥） | 集成测试 |

**覆盖率要求**：
- `judge_eval.py`：F1 计算逻辑 100% 覆盖
- 基线评估：关键词提取、经验提取、学历提取 100% 覆盖
- 模拟评估：噪声注入逻辑 100% 覆盖
- 真实评估：端到端流程覆盖（需 API 密钥）

**Mock 策略**：
- API 调用 → `unittest.mock.patch` 或 `responses` 库
- 文件系统 → `tempfile` + `pathlib`
- 时间 → `freezegun`

## 7. 变更管理

### 修改检查清单

- [ ] 修改黄金集后是否重新运行了所有评估层？
- [ ] 新增评估脚本是否遵循 JSONL 输入输出格式？
- [ ] 是否更新了 `annotation_guideline.md`？
- [ ] 是否更新了质量门禁阈值？
- [ ] 是否更新了 `qwen_comparison_guide.md`？
- [ ] 是否与 `starmap-contracts/openapi.yaml` 的数据格式一致？

### 契约影响
- 评估脚本输出的数据格式应与 `starmap-contracts/models/` 的 Pydantic 模型一致
- 黄金集字段变更需同步更新所有评估脚本
- 后端 API 变更可能影响 `run_real_eval.py` 的数据获取

### 迁移要求
- 新增评估层：需定义与现有层的接口和数据格式
- 黄金集更新：需重新运行所有评估层生成新的基线
- 质量门禁调整：需评估对现有评估结果的影响
- API 密钥变更：需更新 `.env` 文件和相关脚本
