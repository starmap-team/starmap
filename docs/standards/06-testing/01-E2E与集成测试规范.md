# E2E 与集成测试规范文档

## 1. 模块概述

### 职责定位
E2E（End-to-End）与集成测试模块是 StarMap 项目的质量守门人，负责验证全链路业务流程、跨服务数据一致性以及前后端契约对齐。

### 核心目标
1. **冒烟测试**：每日自动验证 main 分支"随时可演示"
2. **E2E 全流程**：覆盖 JD 抽取 -> 图谱写入 -> 匹配诊断 -> 学习路径的完整闭环
3. **集成一致性**：验证 Extract->Graph->Match->Learning->Loop 跨服务数据流
4. **契约对齐**：前后端 API 路由、字段、类型的一致性校验
5. **浏览器 QA**：通过 Playwright 进行前端视觉与交互自动化测试

### 在系统中的位置
```
┌─────────────────────────────────────────┐
│           E2E / 集成测试层               │
├─────────────────────────────────────────┤
│  tests/e2e/      │  浏览器 QA + 冒烟    │
│  tests/integration/│  API 契约 + 联调    │
│  tests/contract/   │  OpenAPI 向后兼容   │
│  tests/unit/       │  Playwright 前端单测 │
│  backend/tests/    │  76 文件 18524 行   │
│  crawler/tests/    │  12 单元/集成测试   │
└─────────────────────────────────────────┘
```

## 5. 编码规范（本模块特有）

### 5.1 测试分层原则
- **严禁 mock**：E2E 测试必须请求真实后端（`full_e2e_test.py` 明确标注"禁止 mock 数据"）
- **离线/在线分离**：`pipeline_smoke_test.py` 中断言 3/6/7 离线可跑，断言 1/2/5/8 需网络
- **跳过优于失败**：网络依赖测试使用 `pytest.skip()` 而非强制失败

### 5.2 Playwright 规范
- 截图目录：`tests/e2e/browser_qa_screenshots/`
- 视口尺寸：`1440x900`
- 区域设置：`zh-CN`
- 无头模式：`headless=True`（CI 环境）

### 5.3 日志与颜色编码
```python
class Colors:
    GREEN = "\033[92m"   # PASS
    RED = "\033[91m"     # FAIL
    YELLOW = "\033[93m"  # WARN
    CYAN = "\033[96m"    # INFO
```

### 5.4 反模式
- **不要在 E2E 测试中直接操作数据库**：通过 API 验证数据状态
- **不要使用 time.sleep() 作为等待策略**：优先使用 Playwright 的 `wait_until`
- **不要硬编码测试数据 ID**：通过 API 动态获取
- **不要忽略 UnicodeEncodeError**：Windows 终端兼容处理（已修复）

### 5.5 严苛闭环策略（D-01/D-04）
```python
# test_loop_5steps.py 中的核心约定
# 任意一步失败立即标 FAILED，不静默降级
# Neo4j/LLM 不可用时 FAILED 冒泡，不允许假成功
```

## 6. 测试规范

### 6.1 覆盖率要求
- **后端**：pytest 覆盖率门禁 60%（CI 强制）
- **前端**：vitest + typecheck 通过
- **爬虫**：compile 检查 + pytest 通过
- **E2E**：8 个 pipeline 断言全部通过

### 6.2 测试矩阵

| 测试类型 | 工具 | 触发时机 | 目标环境 |
|---------|------|---------|---------|
| 单元测试 | pytest / vitest | 每次 PR / push | 本地 / CI |
| 集成测试 | vitest + axios | 每次 PR / push | 本地 / CI |
| 契约校验 | diff_openapi.py | 每次 PR / push | CI |
| 冒烟测试 | pytest / requests | 每日 UTC 02:00 | 远程服务器 |
| 浏览器 QA | Playwright | 手动 / 定时 | 本地 / CI |
| Docker 冒烟 | docker compose | workflow_dispatch / schedule | CI |

### 6.3 Mock 策略
- **E2E 层**：不使用 mock，全部真实调用
- **集成测试层**：使用真实后端，数据依赖种子加载
- **单元测试层**：允许 mock 外部依赖（DB/LLM/Neo4j）
- **前端单元测试**：Playwright 操作真实 DOM

### 6.4 测试数据管理
- 种子数据：`scripts/seed_jd_data.py`, `scripts/seed_demo_data.py`
- 演示数据验证：通过 `/quality/dashboard` 检查 `total_nodes > 0`
- 清理策略：Docker 冒烟后执行 `docker compose down -v`

## 7. 变更管理

### 修改 E2E/集成测试时的检查清单

- [ ] 新增 API 端点是否在 `api-contract.test.ts` 和 `api-integration.test.ts` 中添加对应测试？
- [ ] 新增字段是否更新前后端一致性测试（`CON-01`）？
- [ ] 修改响应 schema 是否同步更新 `openapi_phase1.json` 基线？
- [ ] 契约变更是否运行 `diff_openapi.py` 验证向后兼容？
- [ ] 新增 E2E 场景是否添加到 `smoke_test.py` 的 4 大场景中？
- [ ] 新增 Pipeline 断言是否标记 `pytest.mark.smoke` 和 `pytest.mark.e2e`？
- [ ] 浏览器 QA 是否覆盖新增页面/组件？
- [ ] 测试超时设置是否合理（LLM 调用 120s，普通 API 10-30s）？

### 契约影响
- **修改 `diff_openapi.py`**：影响 CI 契约校验阶段，需确保基线文件存在
- **修改 `api-contract.test.ts`**：影响前端 CI 阶段，需确保后端服务可访问
- **修改 `smoke_test.py`**：影响每日集成演示就绪判断

### 迁移要求
- 新增 E2E 测试文件需放入 `tests/e2e/` 并遵循命名规范 `test_*.py` 或 `*_test.py`
- 新增浏览器 QA 需更新截图目录清理策略（`.gitignore` 已排除）
- 新增集成测试需使用 vitest + axios，避免引入额外测试框架
