# 项目规范总纲

## 权威顺序

- 开发规则：根 `AGENTS.md`。
- API 契约：`starmap-contracts/openapi.yaml`。
- 后端 API 模型：`backend/app/schemas/`。
- 数据库结构：ORM + Alembic。
- 运行方式：根 README、Compose 与环境模板。
- 历史证据：`docs/archive/`，不能覆盖当前实现。

## 强制规则

1. API 变更先改契约，再同步后端、JSON Schema 和前端类型。
2. 路由层不内联新的 Pydantic API 模型。
3. 模型变化必须新增 Alembic migration。
4. API 字段跨端统一使用 `snake_case`。
5. 技能抽取必须保留来源和可信度。
6. PostgreSQL 是业务事实源，Neo4j 是图投影。
7. 配置和密钥来自环境，不硬编码到代码或文档。
8. 提交前运行受影响范围的 lint、typecheck、测试和 baseline。
9. 一次性报告进入 `docs/archive/`，不进入根目录或源码目录。

## 质量命令

```bash
cd backend && poetry run ruff check . && poetry run mypy app && poetry run pytest
cd frontend && npm run lint && npm run typecheck && npm run test && npm run build
python starmap-contracts/validate.py
pwsh -File scripts/check-docs.ps1
```

覆盖率阈值只以 `backend/pyproject.toml` 为准；CI 行为只以 `.github/workflows/` 为准。
