# 架构设计规范

## 1. 模块概述

本文档定义 StarMap 后端的分层架构设计规范，涵盖 API 层、服务层、核心层、数据层四层结构，以及数据流向、技术栈选型和模块间依赖关系。

**核心目标**：
- 明确各层职责边界，防止职责蔓延（特别是 Neo4j 查询的归属）
- 统一数据流向认知，避免循环依赖
- 为代码审查和重构提供架构层面的判断依据

**在系统中的位置**：本规范是 `00-总纲/02-架构设计规范.md`，所有后端模块规范均须引用并遵循。

## 3. 架构设计

### 3.1 四层架构

```
┌─────────────────────────────────────────────────────────────────┐
│  API 层 (backend/app/api/v1/)                                    │
│  ├─ 22 个路由文件，5767 行                                       │
│  ├─ 职责：HTTP 请求解析、参数校验、调用服务层、返回响应             │
│  ├─ 禁止：直接调用 core/ 层，禁止直接操作数据库                    │
│  └─ 依赖：services/ 层、dependencies.py                        │
├─────────────────────────────────────────────────────────────────┤
│  服务层 (backend/app/services/)                                  │
│  ├─ 12 个文件，2434 行                                           │
│  ├─ 职责：业务逻辑编排、Neo4j 图查询、外部服务调用                 │
│  ├─ 禁止：直接调用 LLM（应通过 core/extraction/llm_client.py）     │
│  └─ 依赖：core/ 层、models/ 层、db/ 层                          │
├─────────────────────────────────────────────────────────────────┤
│  核心层 (backend/app/core/)                                      │
│  ├─ 34 个文件，约 10000 行                                        │
│  ├─ 职责：领域算法、LLM 交互、数据归一化、反幻觉                   │
│  ├─ 禁止：HTTP 相关操作、数据库直接写入（应通过服务层）             │
│  └─ 依赖：models/ 层（仅读取 Schema）                             │
├─────────────────────────────────────────────────────────────────┤
│  数据层                                                          │
│  ├─ PostgreSQL (backend/app/db/, models/)                       │
│  ├─ Neo4j (通过 services/neo4j_service.py 封装)                  │
│  ├─ Redis (通过 services/resources.py 封装)                     │
│  └─ Alembic (backend/alembic/)                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 依赖关系

```
api/v1/ ──► services/ ──► core/ ──► models/
   │           │            │
   │           └────────────┘
   │              (services 可调用 core，core 不可调用 services)
   │
   ▼
dependencies.py (认证/会话)
   │
   ▼
config.py (配置)
```

**依赖规则**：
- API 层 → 服务层 → 核心层 → 数据层（单向依赖）
- 禁止反向依赖（如 core/ 调用 services/）
- 禁止跨层调用（如 api/ 直接调用 core/）
- `dependencies.py` 和 `config.py` 为基础设施层，可被任何层引用

## 4. 接口规范

### 4.1 FastAPI 应用实例

```python
# backend/app/main.py
app = FastAPI(
    title="星图 StarMap API",
    description="人才能力星云导航系统 - 后端 API",
    version="0.1.0",
    lifespan=lifespan,
    docs_url=None if _is_prod else "/docs",
    redoc_url=None if _is_prod else "/redoc",
    openapi_url=None if _is_prod else "/openapi.json",
)
```

### 4.2 路由挂载规范

```python
# backend/app/api/v1/router.py
api_router = APIRouter(dependencies=[Depends(get_current_user)])
api_router.include_router(graph.router, tags=["图谱查询"])
api_router.include_router(position.router, tags=["岗位管理"])
# ... 其他路由
```

### 4.3 依赖注入契约

| 依赖函数 | 返回类型 | 用途 | 环境行为差异 |
|---------|---------|------|------------|
| `get_current_user` | `dict[str, Any]` | 获取当前认证用户 | 生产环境强制 JWT，开发环境允许 dev 用户 |
| `require_admin` | `dict[str, Any]` | 要求 admin 角色 | 生产环境检查 role="admin" |
| `get_db_session` | `AsyncIterator[AsyncSession]` | 获取数据库会话 | 统一使用 asyncpg |
| `get_neo4j_driver` | `Any` | 获取 Neo4j 驱动 | 从 app.state.resources 获取 |
| `get_redis_client` | `Redis | None` | 获取 Redis 客户端 | 从 app.state.resources 获取 |

### 4.4 生命周期契约

```python
# backend/app/main.py - lifespan
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    # 启动：初始化资源（PG/Neo4j/Redis）
    # 启动：若 PIPELINE_BOOTSTRAP=true，30 秒后入队 pipeline run
    # 启动：启动 cron scanner 后台任务
    yield
    # 关闭：停止 cron scanner，释放资源
```

## 5. 编码规范（本模块特有）

### 5.1 中间件规范

| 中间件 | 顺序 | 职责 | 配置 |
|--------|------|------|------|
| CORS | 1 | 跨域控制 | `allow_methods=["GET", "POST", "PUT", "DELETE", "PATCH"]` |
| SecurityHeaders | 2 | 安全响应头 | `X-Content-Type-Options`, `X-Frame-Options` 等 |
| RateLimit | 3 | 速率限制 | 60 秒窗口，每 IP 120 请求（内存滑动窗口） |

### 5.2 全局异常处理

```python
@app.exception_handler(Exception)
async def global_exception_handler(request: Request, exc: Exception) -> JSONResponse:
    # 捕获未处理异常，记录日志，返回通用 500
    # 禁止在生产环境泄露异常详情
```

### 5.3 配置管理规范

- 所有配置项必须通过 `backend/app/config.py` 的 `Settings` 类定义
- 环境变量优先于默认值
- 敏感字段（密码、密钥）使用 `_UNCONFIGURED = "CHANGE_ME_IN_ENV"` 占位
- 生产环境启动时校验：密码长度 >= 32、Redis 必须带密码

### 5.4 反模式

| 反模式 | 说明 | 正确做法 |
|--------|------|---------|
| 在 API 层直接调用 core/ | 破坏分层 | 通过 services/ 层中转 |
| 在核心层操作 HTTP | 职责错位 | 核心层只处理纯算法 |
| 绕过 dependencies.py 直接创建会话 | 资源泄漏风险 | 统一使用 `get_db_session` |
| 在生产环境暴露 docs | 信息泄露 | `docs_url=None if _is_prod else "/docs"` |

## 7. 变更管理

### 7.1 修改检查清单

修改架构相关代码时：

- [ ] 是否新增中间件？是 → 确认顺序不影响现有中间件
- [ ] 是否修改 lifespan？是 → 确认资源释放顺序正确
- [ ] 是否新增依赖注入函数？是 → 在 `dependencies.py` 中定义，在 `router.py` 中引用
- [ ] 是否修改配置项？是 → 更新 `.env.example` 和 `config.py`
- [ ] 是否修改路由前缀？是 → 更新 `starmap-contracts/openapi.yaml`

### 7.2 契约影响

| 变更 | 影响 |
|------|------|
| 新增中间件 | 所有请求增加处理开销，需评估性能影响 |
| 修改 lifespan | 影响启动/关闭流程，需测试资源释放 |
| 修改 `api_router` 前缀 | 影响所有 API 路径，需同步更新契约 |
| 修改认证逻辑 | 影响所有端点，需全量回归测试 |

### 7.3 迁移要求

- 新增中间件时，确保不会与现有中间件冲突（如 CORS 必须在最外层）
- 修改 `config.py` 时，必须同步更新 `.env.example`
- 修改路由结构时，必须同步更新 `starmap-contracts/openapi.yaml`
