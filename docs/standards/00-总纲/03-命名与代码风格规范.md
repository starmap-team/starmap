# 命名与代码风格规范

## 1. 模块概述

本文档定义 StarMap 项目全栈（Python 后端、Vue/TS 前端、SQL 数据库、API 契约）的命名约定与代码风格规范，确保跨团队、跨语言的一致性和可维护性。

**核心目标**：
- 统一命名风格，降低认知负担
- 明确类型注解要求，提升代码可维护性
- 建立文件命名规范，便于快速定位代码

**在系统中的位置**：本规范是 `00-总纲/03-命名与代码风格规范.md`，所有模块的编码规范均须在此基础上细化。

## 4. 接口规范

### 4.1 Python 命名规范

| 类型 | 规范 | 示例 | 反例 |
|------|------|------|------|
| 模块/文件 | `snake_case` | `jd_extract.py`, `match_service.py` | `jdExtract.py`, `MatchService.py` |
| 包目录 | `snake_case` | `core/extraction/`, `api/v1/` | `core/Extraction/`, `api/V1/` |
| 类 | `PascalCase` | `EvolutionOrchestrator`, `MatchService` | `evolution_orchestrator`, `matchService` |
| 函数/方法 | `snake_case` | `extract_from_jd`, `score_skill_match` | `extractFromJd`, `scoreSkillMatch` |
| 变量/参数 | `snake_case` | `match_score`, `skill_name` | `matchScore`, `skillName` |
| 常量 | `UPPER_SNAKE_CASE` | `JD_EXTRACTION_PROMPT`, `MAX_RETRY_COUNT` | `jdExtractionPrompt`, `maxRetryCount` |
| 私有属性 | `_snake_case` | `_rate_buckets`, `_is_prod` | `privateVar` |
| 双下划线 | `__snake_case` | `__resolve_postgres_uri` | 避免使用 |

### 4.2 TypeScript/Vue 命名规范

| 类型 | 规范 | 示例 | 反例 |
|------|------|------|------|
| Vue 单文件组件 | `PascalCase` | `MatchDiagnosis.vue`, `SkillGraph.vue` | `match-diagnosis.vue`, `skill_graph.vue` |
| 普通 TS 文件 | `camelCase` | `useSkillStore.ts`, `apiClient.ts` | `UseSkillStore.ts`, `api_client.ts` |
| 类/接口 | `PascalCase` | `SkillNode`, `MatchResult` | `skillNode`, `match_result` |
| 函数/方法 | `camelCase` | `extractSkills`, `calculateScore` | `extract_skills`, `calculate_score` |
| 变量/属性 | `camelCase` | `matchScore`, `skillName` | `match_score`, `skill_name` |
| 常量 | `UPPER_SNAKE_CASE` | `API_TIMEOUT`, `MAX_SKILLS` | `apiTimeout`, `maxSkills` |
| 组合式函数 | `useXxx` | `useSkillStore`, `useGraphData` | `skillStore`, `graphData` |
| 事件回调 | `handleXxx` / `onXxx` | `handleClick`, `onSkillSelect` | `clickHandler`, `skillSelect` |

### 4.3 API 字段命名规范

**铁律**：API 字段统一使用 `snake_case`，前后端一致，**不做 camelCase 转换**。

| 场景 | 规范 | 示例 |
|------|------|------|
| 请求/响应字段 | `snake_case` | `match_score`, `skill_name`, `created_at` |
| 查询参数 | `snake_case` | `page_size`, `sort_by` |
| 路径参数 | `snake_case` | `/positions/{position_id}` |
| 枚举值 | `snake_case` | `"in_progress"`, `"high_trust"` |

**前端类型定义示例**：
```typescript
// 前端也必须使用 snake_case，不做转换
interface MatchResult {
  match_score: number;      // 不是 matchScore
  skill_name: string;       // 不是 skillName
  created_at: string;       // 不是 createdAt
  gap_analysis: GapItem[];  // 不是 gapAnalysis
}
```

### 4.4 SQL/数据库命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 表名 | `snake_case`，复数 | `pipeline_runs`, `skill_records` |
| 列名 | `snake_case` | `created_at`, `match_score` |
| 索引名 | `idx_表名_列名` | `idx_pipeline_runs_status` |
| 外键名 | `fk_表名_引用表` | `fk_pipeline_runs_schedule_id` |
| 约束名 | `uq_表名_列名` | `uq_skill_records_name` |
| 序列名 | `表名_列名_seq` | `pipeline_runs_id_seq` |
| Alembic 迁移 | `XXX_描述.py` | `001_initial_migration.py` |

## 5. 编码规范（本模块特有）

### 5.1 Python 类型注解规范

```python
# 每个文件第一行必须是
from __future__ import annotations

# 函数签名必须有类型注解
def extract_from_jd(
    jd_text: str,
    options: dict[str, Any] | None = None,
) -> list[SkillRecord]:
    ...

# 类属性必须有类型注解
class MatchResult:
    match_score: float
    skill_name: str
    gaps: list[GapItem]

# 异步函数返回类型
def get_db_session() -> AsyncIterator[AsyncSession]:
    ...
```

### 5.2 TypeScript 类型规范

```typescript
// 严格模式启用
// tsconfig.json: "strict": true

// 接口定义
interface SkillNode {
  id: string;
  name: string;
  match_score: number;  // snake_case，与 API 一致
  children?: SkillNode[];
}

// 函数类型
function calculateMatchScore(
  resume: ResumeData,
  position: PositionData,
): number {
  ...
}

// Vue 组件 Props
defineProps<{
  skillName: string;
  matchScore: number;
  isActive?: boolean;
}>();
```

### 5.5 反模式清单

| 编号 | 反模式 | 说明 | 正确做法 |
|------|--------|------|---------|
| N-01 | Python 文件使用 PascalCase | 与 PEP 8 冲突 | `snake_case.py` |
| N-02 | Vue 文件使用 snake_case | 与 Vue 社区规范冲突 | `PascalCase.vue` |
| N-03 | API 字段使用 camelCase | 违反项目约定 | `snake_case` |
| N-04 | 缺少 `from __future__ import annotations` | 类型注解不完整 | 文件首行添加 |
| N-05 | 函数签名缺少返回类型 | mypy 无法检查 | 添加 `-> ReturnType` |
| N-06 | 使用 `Any` 作为万能类型 | 类型安全丧失 | 定义具体类型或 TypeVar |
| N-07 | 混合命名风格（同文件内） | 认知负担 | 统一遵循本规范 |
| N-08 | 数据库表名使用单数 | SQL 惯例 | 复数形式 |

## 7. 变更管理

### 7.1 修改检查清单

修改命名或风格相关代码时：

- [ ] 是否新增公共 API？是 → 确认字段名使用 `snake_case`
- [ ] 是否新增 Vue 组件？是 → 确认文件名使用 `PascalCase.vue`
- [ ] 是否新增 Python 模块？是 → 确认文件名使用 `snake_case.py`
- [ ] 是否修改类型定义？是 → 同步更新前后端类型
- [ ] 是否新增数据库表？是 → 确认表名使用复数 `snake_case`

### 7.2 契约影响

| 变更 | 影响 |
|------|------|
| 修改 API 字段名 | 前后端类型定义、契约文件、文档均需同步 |
| 修改数据库列名 | Alembic 迁移、ORM 模型、查询代码均需同步 |
| 修改文件名 | 导入路径、测试文件、文档引用均需同步 |
| 新增命名规范 | 需更新本规范文档，并在 PR 中说明 |

### 7.3 迁移要求

- 重命名文件时，使用 Git 的 `git mv` 保持历史记录
- 修改 API 字段名时，提供前后兼容方案（如同时支持新旧字段名）
- 修改数据库列名时，必须通过 Alembic 迁移，禁止直接修改生产数据库
