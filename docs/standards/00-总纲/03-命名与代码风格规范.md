# 命名与代码风格规范

## Python

- 文件、变量、函数：`snake_case`；类：`PascalCase`；常量：`UPPER_SNAKE_CASE`。
- 新模块使用 `from __future__ import annotations` 和完整类型注解。
- Ruff 行宽和规则以 `backend/pyproject.toml` 为准。
- FastAPI/Pydantic 使用 v2 写法；SQLAlchemy 使用 async 2.x 风格。

## Vue/TypeScript

- Vue 文件和组件：`PascalCase`；变量/函数：`camelCase`；composable：`useXxx`。
- API 字段保持 `snake_case`；仅 UI 内部状态可使用 camelCase。
- 禁止用宽泛 `any` 或无解释断言掩盖契约错误。
- 页面、Store、composable、组件按责任拆分，避免重复 API/状态逻辑。

## API/数据库

- REST 路径使用稳定业务名；字段使用 `snake_case`。
- ORM 表/列和迁移使用 `snake_case`。
- 错误码使用 `ErrorCode` 枚举，不在路由随意创建字符串。
- 时间统一使用带时区值；ID 使用明确的 UUID/string 契约。

## 文件命名

沿用仓库已有简洁业务名，例如 `graph.py`、`match_service.py`、`MatchDiagnosis.vue`。不要用 `new`、`improved`、`v2` 作为长期并行实现后缀；迁移完成后保留一个规范名称，旧材料归档。

## 工具

格式和静态检查以 Ruff、mypy、ESLint 和 vue-tsc 的实际配置为准，不在文档复制规则版本或通过数量。
