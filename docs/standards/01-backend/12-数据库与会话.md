# 数据库与会话规范

## 1. 模块概述

数据库与会话模块是 StarMap 后端的数据持久化基础设施，包含 PostgreSQL 异步连接管理、数据访问层（Repository）和 Alembic 数据库迁移。该模块位于 `backend/app/db/` 和 `backend/app/repositories/`，以及 `backend/alembic/`。

**核心目标**：
- 提供统一的异步 SQLAlchemy 引擎和会话工厂
- 实现数据访问层（Repository 模式）
- 管理数据库迁移（Alembic）
- 支持连接池管理和性能优化

**在系统中的位置**：位于 `backend/app/db/` 和 `backend/app/repositories/`，被 `services/` 层和 `core/` 层引用。

### 5.2 Repository 模式规范

```python
# repositories/position_repository.py
class PositionRepository:
    def __init__(self, session: AsyncSession) -> None:
        self._session = session

    async def get(self, position_id: uuid.UUID) -> PositionRecord | None:
        result = await self._session.execute(
            select(PositionRecord).where(PositionRecord.id == position_id)
        )
        return result.scalar_one_or_none()
```

### 5.3 反模式

| 反模式 | 说明 | 正确做法 |
|--------|------|---------|
| 绕过 session.py 创建引擎 | 连接池不一致 | 使用 `get_async_engine()` |
| 直接操作数据库 | 绕过 ORM | 使用 Repository 模式 |
| 跳过 Alembic 迁移 | 数据不一致 | 使用 Alembic 管理迁移 |
| 在 Repository 中写业务逻辑 | 职责错位 | Repository 只负责数据访问 |

## 7. 变更管理

### 7.1 修改检查清单

修改数据库与会话模块时：

- [ ] 是否修改连接池配置？是 → 评估性能影响
- [ ] 是否新增 Repository？是 → 添加对应测试
- [ ] 是否新增迁移？是 → 验证迁移正确性
- [ ] 是否修改表结构？是 → 生成 Alembic 迁移

### 7.2 契约影响

| 变更 | 影响 |
|------|------|
| 修改连接池配置 | 影响数据库连接性能 |
| 新增 Repository | 影响数据访问层 |
| 新增迁移 | 影响数据库结构 |
| 修改表结构 | 影响现有数据 |

### 7.3 迁移要求

- 任何模型变更必须通过 Alembic 迁移
- 迁移文件命名：`XXX_描述.py`
- 迁移前必须备份数据
- 迁移后必须验证数据完整性
