# 入口与配置规范

## 1. 模块概述

本模块为 StarMap 后端应用的入口层与配置层，包含 `main.py`（FastAPI 应用入口）、`config.py`（配置中心）和 `dependencies.py`（依赖注入与认证）。

**核心目标**：
- 提供统一的 FastAPI 应用实例和生命周期管理
- 集中管理环境配置，支持开发/生产环境差异化行为
- 提供标准的依赖注入机制，特别是认证基础设施

**在系统中的位置**：位于 `backend/app/` 目录，是所有请求的入口点，被 `uvicorn` 直接加载。

## 4. 接口规范

### 4.1 FastAPI 应用实例

```python
app = FastAPI(
    title="星图 StarMap API",

    version="0.1.0",
    lifespan=lifespan,
    docs_url=None if _is_prod else "/docs",
    redoc_url=None if _is_prod else "/redoc",
    openapi_url=None if _is_prod else "/openapi.json",

```

### 4.2 生命周期 (lifespan)

```python
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    # 启动：
    #   1. 初始化资源（PG/Neo4j/Redis）
    #   2. 若 PIPELINE_BOOTSTRAP=true，30 秒后入队 pipeline run
    #   3. 启动 cron scanner 后台任务（60 秒间隔）
    yield
    # 关闭：
    #   1. 停止 cron scanner
    #   2. 释放资源
```

### 4.3 中间件顺序

| 顺序 | 中间件 | 类名 | 职责 |
|------|--------|------|------|
| 1 | CORS | `CORSMiddleware` | 跨域控制，限制 methods/headers |
| 2 | SecurityHeaders | `SecurityHeadersMiddleware` | 添加安全响应头 |
| 3 | RateLimit | `RateLimitMiddleware` | 内存滑动窗口限流（60s/120req/IP） |

## 5. 编码规范（本模块特有）

### 5.1 生产环境安全铁律

| 规则 | 实现 | 违反后果 |
|------|------|---------|
| 禁用 Swagger/ReDoc/OpenAPI | `docs_url=None if _is_prod` | 信息泄露 |
| 生产环境必须配置真实密钥 | `len(secret_key) >= 32` | 安全漏洞 |
| 生产环境 Redis 必须有密码 | `"@" in redis_uri` | 未授权访问 |
| 敏感配置使用占位符 | `_UNCONFIGURED = "CHANGE_ME_IN_ENV"` | 误用默认密码 |
| 健康检查不暴露版本号 | `_is_prod` 判断 | 信息泄露 |

### 5.2 日志配置

```python
# 生产环境：JSON 结构化日志（ELK/Loki 兼容）
logger.add(sys.stderr, serialize=True, level=settings.app_log_level)

# 开发环境：彩色格式化日志
logger.add(sys.stderr, level=settings.app_log_level, format="...")
```

### 5.3 JWT 实现细节

- 算法：HMAC-SHA256
- 密钥来源：`settings.secret_key`
- 开发环境固定 token：`"dev-token"`
- 过期检查：payload 中的 `exp` 字段

### 5.4 反模式

| 反模式 | 说明 | 正确做法 |
|--------|------|---------|
| 在 main.py 中写业务逻辑 | 入口层应保持精简 | 业务逻辑放在 services/ 或 core/ |
| 绕过 config.py 直接读取环境变量 | 配置分散 | 统一通过 `settings` 访问 |
| 在 dependencies.py 中写认证逻辑 | 职责不清 | 认证逻辑放在 services/ |
| 生产环境使用默认密码 | 安全漏洞 | 启动时校验并拒绝 |

## 7. 变更管理

### 7.1 修改检查清单

修改入口与配置模块时：

- [ ] 是否新增中间件？是 → 确认顺序不影响现有中间件
- [ ] 是否修改 lifespan？是 → 确认资源释放顺序正确
- [ ] 是否新增配置项？是 → 更新 `.env.example` 和 `config.py`
- [ ] 是否修改认证逻辑？是 → 全量回归测试
- [ ] 是否修改日志格式？是 → 确认不影响日志收集系统

### 7.2 契约影响

| 变更 | 影响 |
|------|------|
| 新增中间件 | 所有请求增加处理开销 |
| 修改 lifespan | 影响启动/关闭流程 |
| 修改 `api_router` 前缀 | 影响所有 API 路径 |
| 修改认证逻辑 | 影响所有端点 |
| 新增配置项 | 需更新 `.env.example` 和部署脚本 |

### 7.3 迁移要求

- 新增配置项时，必须同步更新 `.env.example`
- 修改认证逻辑时，必须同步更新 `starmap-contracts/openapi.yaml` 中的安全定义
- 修改中间件时，必须评估对性能的影响
