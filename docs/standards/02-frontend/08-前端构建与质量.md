# 前端构建与质量 规范文档

## 1. 模块概述

**职责定位**：前端工程化基础设施，负责项目构建、类型检查、代码质量保障及开发环境配置。

**核心目标**：
- 提供快速的开发构建（Vite）和优化的生产构建
- 确保 TypeScript 类型安全
- 通过 ESLint 维护代码质量和一致性
- 支持代码分割和懒加载优化

**在系统中的位置**：
- 上游：`starmap-contracts/openapi.yaml`（API 契约，驱动 schema 生成）
- 下游：所有 `src/` 下的源代码
- 依赖：Node.js、npm

## 5. 编码规范（本模块特有）

### 5.1 构建优化
- 代码分割：按 vendor 分组（vue、echarts、element、g6 等）
- 懒加载：所有页面组件使用 `() => import('@/pages/*.vue')`
- chunk 大小警告阈值：600KB
- 生产构建前必须执行 `vue-tsc --noEmit` 类型检查

### 5.2 TypeScript 严格模式
- `strict: true` 开启所有严格检查
- `noEmit: true` 仅做类型检查，不输出文件
- `isolatedModules: true` 确保每个文件可独立编译
- `skipLibCheck: true` 跳过第三方库类型检查（加速编译）

### 5.3 ESLint 规则
- `vue/multi-word-component-names: off` — 允许单字组件名（如 `Home.vue`）
- `@typescript-eslint/no-explicit-any: off` — 允许 `any`（渐进式类型化）
- `@typescript-eslint/no-unused-vars: warn` — 未使用变量警告（忽略 `_` 前缀参数）
- `no-empty: error` — 禁止空块（但允许空 catch）
- `src/api/schema.ts` 被忽略（自动生成文件）

### 5.4 依赖管理
- 生产依赖：Vue 3、Vue Router、Pinia、Element Plus、ECharts、Axios、@antv/g6
- 开发依赖：Vite、TypeScript、ESLint、Vitest、Playwright
- `openapi-typescript` 用于从 `openapi.yaml` 生成类型定义

### 5.5 反模式
- **禁止**在生产构建中保留 `console.log`（应使用 `import.meta.env.DEV` 条件输出）
- **禁止**直接修改 `node_modules` 中的文件
- **禁止**在 `package.json` 中使用 `*` 版本号（应锁定具体版本）
- **禁止**在 `vite.config.ts` 中硬编码敏感信息（如 API 密钥）

## 6. 测试规范

| 测试类型 | 工具 | 配置 | 命令 |
|---------|------|------|------|
| 单元测试 | Vitest | `vite.config.ts` 中 `test` 配置 | `npm run test` |
| E2E 测试 | Playwright | `playwright.config.ts` | `npx playwright test` |
| 类型检查 | vue-tsc | `tsconfig.json` | `npm run typecheck` |
| 代码质量 | ESLint | `.eslintrc.json` | `npm run lint` |

**覆盖率要求**：
- 单元测试：核心 composables 和 utils 的函数覆盖率 >= 80%
- E2E 测试：覆盖主要用户流程（首页、闭环演示、匹配诊断）
- 类型检查：0 错误
- ESLint：0 错误，最多 50 个警告

## 7. 变更管理

- [ ] 修改 `vite.config.ts` 后是否测试了开发和生产构建？
- [ ] 修改 `tsconfig.json` 后是否执行了 `npm run typecheck`？
- [ ] 新增依赖是否更新了 `package.json` 和 `package-lock.json`？
- [ ] 修改 ESLint 规则后是否执行了 `npm run lint`？
- [ ] 新增脚本是否更新了 README 文档？
- [ ] 修改 Docker 构建后是否测试了镜像构建？

### 契约影响
- `gen:api` 脚本依赖 `starmap-contracts/openapi.yaml`，契约变更后需重新生成
- API 路径变更可能影响 Vite 代理配置
- 后端 API 版本升级可能需要同步更新 `package.json` 中的 `openapi-typescript` 版本

### 迁移要求
- Vite 版本升级：需检查插件兼容性（如 `@vitejs/plugin-vue`）
- TypeScript 版本升级：需检查 `strict` 模式新增的检查项
- ESLint 版本升级：需检查规则变更和插件兼容性
- 依赖版本升级：需运行完整测试套件验证
