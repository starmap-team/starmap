# 样式与设计令牌 规范文档

## 1. 模块概述

**职责定位**：前端视觉设计系统的核心，定义全局 CSS 自定义属性（设计令牌）、动画系统、响应式断点及图表主题桥接，确保全站视觉一致性。

**核心目标**：
- 定义完整的设计令牌系统（颜色、字体、间距、阴影、圆角、动画）
- 支持明暗双主题切换
- 提供响应式布局系统
- 为 ECharts/G6 图表提供运行时主题桥接

**在系统中的位置**：
- 上游：无（设计令牌是视觉系统的根）
- 下游：`App.vue`（全局样式覆盖）、`components/`（组件样式）、`pages/`（页面样式）
- 依赖：`utils/chartTheme.ts`（CSS 变量 → ECharts 主题桥接）

## 5. 编码规范（本模块特有）

### 5.1 CSS 变量命名约定
- 使用 `--{category}-{name}` 格式（如 `--primary-hover`）
- 语义化命名，避免使用具体颜色值作为变量名
- 暗色主题在 `html.dark` 中覆盖对应变量

### 5.2 动画性能
- 仅使用 `transform` 和 `opacity` 属性进行动画
- 避免动画 `width`、`height`、`top`、`left` 等会触发重排的属性
- 尊重 `prefers-reduced-motion` 媒体查询

### 5.3 响应式设计
- 使用 CSS 变量控制布局参数，而非硬编码像素值
- 响应式断点：`1920px` / `1440px` / `1024px` / `768px`
- 移动端优先或桌面优先均可，但需保持全站一致

### 5.4 图表主题桥接
- `chartTheme.ts` 的 `cv()` 函数读取 CSS 变量，确保图表与 UI 主题同步
- `_cvCache` 缓存计算结果，避免频繁 DOM 查询
- 图表颜色使用 `chartColors()` 动态获取，而非硬编码

### 5.5 反模式
- **禁止**在组件中硬编码颜色值（应使用 CSS 变量）
- **禁止**在组件中定义全局 CSS 变量（应在 `App.vue` 或 `design-tokens.css` 中定义）
- **禁止**在 JavaScript 中直接读取 `getComputedStyle`（应使用 `chartTheme.ts` 的 `cv()`）
- **禁止**使用 `!important` 覆盖 Element Plus 样式（应在 `App.vue` 中统一处理）

## 7. 变更管理

### 修改检查清单

- [ ] 新增 CSS 变量是否遵循 `--{category}-{name}` 命名？
- [ ] 新增变量是否在 `html.dark` 中有对应覆盖？
- [ ] 修改颜色值是否影响图表主题（需同步更新 `chartTheme.ts`）？
- [ ] 新增动画是否仅使用 `transform` + `opacity`？
- [ ] 是否尊重 `prefers-reduced-motion`？
- [ ] 新增响应式样式是否覆盖所有断点？

### 契约影响
- CSS 变量变更需同步更新 `chartTheme.ts` 的读取逻辑
- 颜色值变更需确认 `graphColors.ts` 的调色板是否受影响
- 间距/字体变更需检查所有组件的样式是否对齐

### 迁移要求
- CSS 变量重命名：需全局搜索替换所有引用
- 主题切换：从单主题迁移到双主题时，需检查所有硬编码颜色值
- 图表主题：新增图表类型时，需确认 `chartTheme.ts` 已提供对应配置
