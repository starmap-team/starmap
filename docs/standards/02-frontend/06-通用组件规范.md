# 通用组件规范文档

## 1. 模块概述

**职责定位**：可复用的 UI 组件库，为页面组件（pages/）和布局组件（layouts/）提供原子化、可组合的 UI 元素。

**核心目标**：
- 提供 38 个高复用性的 Vue 组件
- 组件职责单一，输入（props）输出（emits）明确
- 支持明暗双主题，与 `styles/design-tokens.css` 设计令牌对齐
- 图表组件（Graph2D/Graph3D）作为系统的视觉核心

**在系统中的位置**：
- 上游：`utils/`（工具函数）、`types/`（类型定义）
- 下游：`pages/`（页面组件）、`layouts/`（布局组件）
- 依赖：`stores/`（部分组件读取 store 数据）

## 4. 接口规范

### 4.1 Graph2D 组件接口

```vue
<script setup lang="ts">
const props = withDefaults(defineProps<{
  layoutMode?: 'force' | 'dagre' | 'radial'
  kaColorMap?: Map<string, string>
  showEvolution?: boolean
  maxNodesLimit?: number
  proficiencyFilter?: string[]
}>(), {
  layoutMode: 'force',
  kaColorMap: () => new Map(),
  showEvolution: false,
  maxNodesLimit: 80,
  proficiencyFilter: () => ['精通', '熟悉', '了解']
})

const emit = defineEmits<{
  nodeClick: [nodeId: string]
  nodeDblClick: [nodeId: string]
  canvasClick: []
  edgeClick: [edgeData: EvolutionEdgeClickPayload]
}>()
</script>
```

## 5. 编码规范（本模块特有）

### 5.1 组件命名约定
- **必须**使用 PascalCase（如 `Graph2D.vue`）
- **必须**使用多词组件名（避免与 HTML 元素冲突）
- 图表组件以 `Chart` 结尾（如 `QualityTrendChart`）
- 面板组件以 `Panel` 结尾（如 `DetailPanel`）
- 卡片组件以 `Card` 结尾（如 `DataSourceCard`）

### 5.2 Props 约定
- **必须**使用 `withDefaults(defineProps<...>(), { ... })` 定义默认值
- **必须**为可选 props 提供默认值
- **推荐**使用接口（interface）定义复杂 props
- 事件回调通过 `emits` 定义，不通过 props 传递

### 5.3 样式约定
- 组件样式使用 `<style scoped>` 或 `<style module>`
- 全局样式覆盖在 `App.vue` 中统一处理
- 组件内部使用 CSS 变量（`var(--primary)` 等）实现主题适配
- 动画仅使用 `transform` + `opacity`，避免触发重排

### 5.4 图表组件约定
- 图表组件接收 `option` prop（ECharts option 对象），不内部生成
- 图表主题通过 `utils/chartTheme.ts` 统一获取
- 图表实例在 `onUnmounted` 中销毁，避免内存泄漏
- 响应式尺寸通过 `ResizeObserver` 或 `window.resize` 监听

### 5.5 反模式
- **禁止**组件直接调用 API（应通过 store 或 composable）
- **禁止**组件之间直接 import（通过 props/emits 或 store 通信）
- **禁止**在组件中定义可复用的工具函数（应提取到 `utils/`）
- **禁止**使用 Options API（必须使用 `<script setup>`）
- **禁止**组件内部硬编码样式值（应使用 CSS 变量）

## 7. 变更管理

### 修改检查清单

- [ ] 新增组件是否使用 PascalCase 命名？
- [ ] 新增组件是否使用多词命名？
- [ ] Props 是否都有默认值（或明确为必填）？
- [ ] 是否定义了 emits？
- [ ] 样式是否使用 scoped 或 CSS 变量？
- [ ] 是否处理了组件卸载时的清理（如销毁图表实例）？
- [ ] 是否与 `starmap-contracts` 的模型字段名一致？

### 契约影响
- 组件 props 的字段名应与 `starmap-contracts/models/` 的 Pydantic 模型字段名对齐
- 图表组件的数据格式应与后端 API 响应格式一致

### 迁移要求
- 组件重命名：需同步更新所有引用该组件的文件
- Props 变更：新增/删除/重命名 props 时，需检查所有引用方
- 组件拆分：将一个组件拆分为多个时，需更新父组件的引用
