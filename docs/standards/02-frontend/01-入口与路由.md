# 入口与路由 规范文档

## 1. 模块概述

**职责定位**：前端应用的启动入口与客户端路由中枢，负责 Vue 应用实例创建、全局依赖注入、页面导航管理及认证守卫。

**核心目标**：
- 提供一致的应用初始化流程（Pinia + Vue Router + Element Plus + ECharts）
- 实现 14 条业务路由的声明式配置，全部懒加载以优化首屏
- 通过路由守卫实现认证/授权控制，与 API 层的 401 处理形成闭环

**在系统中的位置**：
- 上游：浏览器环境（localStorage、Cookie、DOM）
- 下游：所有 pages/ 页面组件、stores/ 状态管理、api/ 请求层
- 契约依赖：`starmap-contracts/openapi.yaml` 定义的路径结构与路由命名对齐

## 3. 架构设计

```
┌─────────────────────────────────────────────────────────┐
│  Browser (localStorage, Cookie, DOM Events)              │
├─────────────────────────────────────────────────────────┤
│  main.ts                                                │
│  ├── createApp(App)                                     │
│  ├── app.use(createPinia())    → stores/                │
│  ├── app.use(router)           → router/index.ts        │
│  ├── app.use(ElementPlus)      → UI 组件库              │
│  └── app.component('VChart')   → vue-echarts 全局注册  │
├─────────────────────────────────────────────────────────┤
│  App.vue                                                │
│  ├── CSS 自定义属性（设计令牌）→ styles/ 消费            │
│  ├── 页面过渡动画（slide-left/right/fade）              │
│  └── <router-view> 挂载点                               │
├─────────────────────────────────────────────────────────┤
│  router/index.ts                                        │
│  ├── 14 routes (全部 () => import('@/pages/*.vue'))     │
│  ├── meta: { title, icon, breadcrumb, requiresAuth }    │
│  ├── beforeEach: 认证守卫 + admin 权限检查              │
│  ├── afterEach: document.title 更新                     │
│  └── window 'auth:unauthorized' 事件监听 → 跳转 /login  │
└─────────────────────────────────────────────────────────┘
```

### 数据流向

1. **启动流**：`main.ts` → `createApp` → 注册插件 → `mount('#app')`
2. **导航流**：用户点击 → `router.beforeEach` → 认证检查 → 懒加载页面组件 → `router.afterEach` 更新标题
3. **认证流**：`request.ts` 401 → 派发 `auth:unauthorized` 事件 → `router` 监听 → 跳转 `/login?redirect=...`

## 5. 编码规范（本模块特有）

### 5.1 路由配置约定
- **必须**为每条路由提供 `name`，用于编程式导航和面包屑
- **必须**提供 `meta.title`，用于 `afterEach` 自动更新 `document.title`
- **必须**使用懒加载，禁止同步导入页面组件
- `meta.requiresAuth` 和 `meta.requiresAdmin` 为可选，仅 `/admin` 需要两者

### 5.2 认证守卫约定
- `isAuthed()` 同步检查 `localStorage` / `Cookie`，避免 Pinia 未初始化时的循环依赖
- 401 处理采用事件总线模式（`auth:unauthorized`），而非直接调用 `useRouter()`
- 未认证用户访问受保护路由 → 重定向到 `/login?redirect=当前路径`

### 5.3 App.vue 全局样式约定
- CSS 自定义属性（`--*`）在 `:root` 和 `html.dark` 中定义，支持明暗双主题
- Element Plus 覆盖样式使用 `!important` 确保优先级
- 动画类（`.page-slide-left-*`、`.page-fade-*`）仅使用 `transform` + `opacity`，保证 GPU 合成

### 5.4 反模式
- **禁止**在 `main.ts` 中引入任何业务 store（避免初始化顺序问题）
- **禁止**在 `request.ts` 中直接 `import { useRouter } from 'vue-router'`（会导致 Pinia/Router 循环）
- **禁止**同步导入页面组件（破坏代码分割）

## 6. 测试规范

| 测试文件 | 覆盖范围 | 策略 |
|---------|---------|------|
| `frontend/e2e/` (Playwright) | 端到端导航、路由守卫、页面过渡 | 真实浏览器环境 |
| `frontend/src/router/__tests__/` (如存在) | 路由守卫逻辑单元测试 | mock `localStorage` + `useUserStore` |

**覆盖率要求**：
- 路由守卫分支覆盖（public path / requiresAuth / requiresAdmin / 已认证 / 未认证）
- 懒加载错误处理（chunk 加载失败时的降级）

**Mock 策略**：
- `localStorage.getItem` → jest.spyOn
- `useUserStore` → 使用 Pinia 的 `createTestingPinia`
- `window.dispatchEvent` → 监听 `auth:unauthorized` 事件

## 7. 变更管理

### 修改检查清单

- [ ] 新增路由是否提供 `name`、`meta.title`、`meta.icon`？
- [ ] 新增路由是否使用懒加载 `() => import(...)`？
- [ ] 是否需要认证/授权？如需要，是否正确设置 `meta.requiresAuth` / `meta.requiresAdmin`？
- [ ] 面包屑路径是否正确？
- [ ] 页面过渡动画名称是否在 `App.vue` 中已定义？
- [ ] 路由路径是否与 `starmap-contracts/openapi.yaml` 的 API 路径语义一致？

### 契约影响
- 路由路径命名应与后端 API 资源路径保持语义对齐（如 `/positions` 对应 `/api/v1/positions`）
- 新增 `meta.requiresAdmin` 路由时，需确认后端 `/api/v1/admin/*` 接口也做了同等权限校验

### 迁移要求
- 路由路径变更 → 需同步更新所有 `router.push({ name: '...' })` 调用（优先使用 `name` 而非 `path`）
- 移除路由 → 检查是否有外部链接/书签引用，考虑添加重定向
