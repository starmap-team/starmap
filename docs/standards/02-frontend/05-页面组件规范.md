# 页面组件规范文档

## 1. 模块概述

**职责定位**：前端的路由级页面组件，每个页面对应一个独立的路由路径，负责业务逻辑的编排、数据获取的触发、子组件的组合及用户交互的处理。

**核心目标**：
- 实现 14 个业务页面的完整功能
- 页面组件作为"容器"，将复杂逻辑委托给 composables 和 stores
- 保持模板层简洁，聚焦页面级布局和交互编排
- 支持响应式布局，适配桌面和移动端

**在系统中的位置**：
- 上游：`router/index.ts`（路由配置，全部懒加载）
- 下游：`components/`（通用组件）、`composables/`（业务逻辑）、`stores/`（状态管理）
- 依赖：`layouts/`（布局组件）

```vue

// 1. 外部库导入
// 2. 组件导入（layouts + components）

// 6. 计算属性
// 7. 方法定义
// 8. 生命周期钩子

<template>
  <!-- 使用 Layout 组件包裹 -->

  </MainLayout>
```

## 5. 编码规范（本模块特有）

### 5.1 页面组件约定
- **必须**使用 `<script setup lang="ts">` 语法
- **必须**使用对应的 Layout 组件包裹（`MainLayout` 或 `DashboardLayout`）
- **推荐**将复杂逻辑提取到 composables，页面组件聚焦编排
- **推荐**单文件行数控制在 500 行以内（`LoopDemo.vue` 1675 行为例外，需逐步拆分）

### 5.2 数据获取约定
- 在 `onMounted` 中触发初始数据获取
- 使用 store 的 loading 状态控制 UI（如 `v-loading`）
- 错误处理通过 `request.ts` 拦截器统一处理，页面层无需重复处理

### 5.3 布局约定
- 使用 CSS Grid / Flexbox 进行页面布局
- 响应式断点：`>=1920px` / `>=1440px` / `>=1024px` / `<1024px` / `<768px`
- 暗色主题通过 `html.dark` 类控制，CSS 变量自动切换

### 5.4 性能优化
- 大页面使用 `defineAsyncComponent` 懒加载子组件
- 图表组件使用 `v-if` 控制渲染，避免不可见时渲染
- 大数据列表使用虚拟滚动（如 Element Plus 的 `el-table` 虚拟滚动）

### 5.5 反模式
- **禁止**在页面组件中直接操作 DOM（应通过 composables 或 ref 处理）
- **禁止**在页面组件中定义可复用的工具函数（应提取到 `utils/`）
- **禁止**页面组件之间直接 import（通过路由和 store 通信）
- **禁止**在页面组件中定义图表 option（应提取到 `composables/use*Charts`）

| 测试文件 | 覆盖范围 | 策略 |
|---------|---------|------|
| `frontend/e2e/home.spec.ts` | 首页：图谱渲染、节点交互、搜索 | Playwright |
| `frontend/e2e/dashboard.spec.ts` | 数据大屏：KPI 展示、图表渲染、SSE | Playwright |
| `frontend/e2e/loop.spec.ts` | 闭环演示：5 步流程、步骤状态 | Playwright |
| `frontend/e2e/match.spec.ts` | 匹配诊断：雷达图、差距分析 | Playwright |

**覆盖率要求**：
- 每个页面至少覆盖主要交互路径（happy path）
- 关键业务页面（LoopDemo、DataDashboard）覆盖异常路径
- 认证相关页面覆盖未认证/无权限场景

**Mock 策略**：
- API 请求 → Playwright `route.fulfill()` 或 MSW（已移除，使用 mock server）
- 认证状态 → mock `localStorage` / Cookie
- 图表渲染 → 截图对比或断言 canvas 存在

## 7. 变更管理

### 修改检查清单

- [ ] 新增页面是否在 `router/index.ts` 中注册路由？
- [ ] 新增页面是否使用懒加载 `() => import('@/pages/XXX.vue')`？
- [ ] 新增页面是否提供 `meta.title` 和 `meta.icon`？
- [ ] 复杂逻辑是否已提取到 composables？
- [ ] 是否使用了正确的 Layout 组件？
- [ ] 是否需要添加 `meta.requiresAuth` / `meta.requiresAdmin`？
- [ ] 页面路径是否与 `starmap-contracts/openapi.yaml` 的 API 路径语义一致？

### 契约影响
- 页面组件通过 store/composable 间接依赖后端 API
- 新增页面需确认对应 API 端点已在 `openapi.yaml` 中定义
- 页面间的数据共享通过 store 实现，不直接传递 props

### 迁移要求
- 页面组件拆分：将大页面拆分为多个子组件时，需同步更新路由（如添加子路由）
- 页面组件合并：合并前需确认无路由引用冲突
- Layout 变更：修改 `MainLayout` 或 `DashboardLayout` 时，需检查所有引用页面
