# 技术债与改进路线

## 1. 模块概述

### 职责定位
本文档记录 StarMap 项目的技术债务和改进路线图，为团队提供系统性的重构指导和依赖升级计划。

### 核心目标
1. **技术债务透明化**：量化当前技术债务，避免"隐形炸弹"
2. **优先级排序**：按影响程度和修复成本排序
3. **时间线规划**：给出合理的升级时间窗口
4. **风险预警**：提前识别升级风险

## 5. 编码规范（本模块特有）

### 5.1 优先级定义
- **P0（紧急）**：影响生产安全或可用性，需立即处理
- **P1（高）**：影响开发效率或代码质量，计划在下个 Sprint 处理
- **P2（中）**：可接受的技术妥协，计划在下个季度处理
- **P3（低）**：锦上添花，有空时处理

### 5.2 反模式
- **不要忽视 P0 债务**：可能引发严重问题
- **不要一次性升级所有依赖**：分批进行，降低风险
- **不要在没有测试的情况下重构**：确保有回归测试覆盖

## 6. 测试规范

### 6.1 升级验证
- 每次依赖升级后运行完整测试套件
- 升级前在 staging 环境验证
- 记录升级过程中的问题和解决方案

## 7. 变更管理

### 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| FastAPI 破坏性变更 | 中间件、依赖注入 API 变更 | 提前阅读迁移指南，在分支测试 |
| Neo4j driver 6.x API 变更 | 连接池、事务 API 变更 | 官方迁移文档、staging 验证 |
| Vite 8 插件不兼容 | 构建失败 | 检查所有插件兼容性、逐步升级 |
| 旧 pipeline 引用遗漏 | 运行时错误 | 全局搜索 + 静态分析 |
| simhash 统一后结果不一致 | 去重逻辑变化 | 对比测试、Golden Set 验证 |
