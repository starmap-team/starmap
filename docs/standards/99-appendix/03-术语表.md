# 术语表

## 1. 模块概述

### 职责定位
本文档汇总 StarMap 项目的专有名词和术语，提供中英对照，帮助团队成员快速理解项目中的专业概念。

### 核心目标
1. **术语统一**：确保团队内对关键术语的理解一致
2. **新人 onboarding**：帮助新成员快速理解项目概念
3. **文档一致性**：为技术文档提供术语参考
4. **跨团队协作**：统一前后端、算法、QA 各组的术语表达

### 在系统中的位置
```
─────────────────────────────────────────┐
│           99-appendix                   │
│  ├─ 01-已知问题清单.md                  │

└─────────────────────────────────────────┘
```

## 4. 接口规范

### 术语记录格式

| 字段 | 说明 | 示例 |
|------|------|------|
| 中文 | 中文名称 | 技能变更影响指数 |
| 英文 | 英文名称 | Change Impact Index |
| 缩写 | 缩写形式 | CII |
| 定义 | 简要定义 | 衡量技能变更对岗位影响的量化指标 |
| 相关模块 | 所属模块 | 演化分析、质量监控 |

## 5. 编码规范（本模块特有）

### 5.1 术语使用规范
- 技术文档中首次出现术语时标注英文
- 代码注释中使用英文术语
- 中文文档中使用中文术语，括号内标注英文

### 5.2 反模式
- **不要混用中英文术语**：同一文档中保持术语一致性
- **不要创造新术语**：优先使用已有术语
- **不要使用已废弃术语**：如 MSW、BOM 等

## 6. 测试规范

### 6.1 术语一致性检查
- 代码注释中的术语与术语表一致
- 文档中的术语与术语表一致
- API 文档中的术语与代码一致

## 7. 变更管理

### 修改本清单时的检查清单

- [ ] 新增术语是否已有定义？
- [ ] 术语缩写是否唯一？
- [ ] 中英文翻译是否准确？
- [ ] 相关模块是否标注正确？
