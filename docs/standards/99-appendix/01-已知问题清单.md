# 已知问题清单

## 1. 模块概述

### 职责定位
本文档汇总 StarMap 项目通过扫描发现的遗留问题，按严重程度分级，为团队提供问题追踪和修复优先级参考。

### 核心目标
1. **问题透明化**：所有已知问题集中记录，避免信息分散
2. **优先级管理**：按严重程度分级，指导修复顺序
3. **风险预警**：提前识别可能影响项目的问题
4. **追踪闭环**：每个问题标注状态和修复计划

## 4. 接口规范

### 问题记录格式

| 字段 | 说明 | 示例 |
|------|------|------|
| ID | 问题编号 | ISSUE-001 |
| Severity | 严重程度 | 🔴 / 🟡 / 🟢 |
| Category | 问题分类 | Git / Dependency / Code / Config |
| Description | 问题描述 | 本地领先远程 220 个提交未推送 |
| Impact | 影响范围 | 代码同步、协作风险 |
| Status | 当前状态 | open / in-progress / resolved |
| Owner | 负责人 | - |
| Plan | 修复计划 | 推送或清理 |

## 5. 编码规范（本模块特有）

### 5.1 问题记录规范
- 每个问题必须有唯一的 ID
- Severity 必须客观评估，避免过度乐观或悲观
- Status 及时更新，resolved 的问题保留历史记录
- 新增问题添加到列表末尾

### 5.2 反模式
- **不要隐藏问题**：所有已知问题必须记录
- **不要低估 Severity**：影响生产的问题必须标为 🔴
- **不要遗漏 Owner**：每个问题必须有人负责跟进

## 6. 测试规范

### 6.1 问题验证
- 修复后需验证问题是否真正解决
- 新增回归测试防止问题复发
- 定期（每月）复查已知问题清单

## 7. 变更管理

### 修改本清单时的检查清单

- [ ] 新增问题是否分配了唯一 ID？
- [ ] Severity 评估是否客观？
- [ ] 是否指定了 Owner？
- [ ] 修复后是否更新了 Status？
- [ ] 是否添加了修复日期？

### 详细说明

#### ISSUE-001: 本地领先远程 220 个提交未推送
**描述**：本地仓库领先远程 main 分支 220 个提交未推送。这可能是由于长期本地开发未同步，或者远程分支已被 force-push 导致历史分叉。
**风险**：
- 代码丢失（本地损坏时）
- 协作困难（其他开发者基于旧代码工作）
- 合并冲突（积累过多）
**修复建议**：
1. 审查本地 220 个提交的变更内容
2. 如果变更有效：创建 PR 分批推送
3. 如果变更无效或已过时：reset 到远程 HEAD
4. 建立每日推送工作流防止复发

#### ISSUE-002: upstream 和 upstream-fork 重复配置
**描述**：Git remote 中同时存在 `upstream` 和 `upstream-fork`，指向相同或不同的仓库。
**风险**：
- 推送目标混淆
- 分支追踪错误
**修复建议**：
1. `git remote -v` 查看当前配置
2. 确定有效 remote 名称
3. `git remote remove` 删除重复配置

#### ISSUE-003: 部分依赖版本较旧
**描述**：多个核心依赖版本落后，包括但不限于：
- `fastapi`: 0.119 -> 0.139
- `neo4j`: 5.28 -> 6.2
- `vite`: 5.4 -> 8.1
**风险**：
- 安全漏洞未修复
- 性能优化未获得
- 新特性无法使用
**修复建议**：参见 `02-技术债与改进路线.md`

#### ISSUE-004: 空目录残留
**描述**：`core/graph_engine/`, `core/hallucination/`, `core/trust/` 三个目录为空，但逻辑已迁移到其他模块。
**风险**：
- 误导新开发者
- 目录结构混乱
**修复建议**：直接删除空目录，更新相关文档。

#### ISSUE-005: 新旧 pipeline 并存
**描述**：`app/pipeline/`（旧版）和 `app/core/pipeline/`（新版）同时存在，代码可能重复或引用混乱。
**风险**：
- 维护困难（修改一处需同步另一处）
- 引用歧义（import 路径不明确）
- 测试覆盖不全
**修复建议**：
1. 梳理所有引用旧 pipeline 的代码
2. 统一迁移到新版
3. 删除旧版目录
4. 更新 import 路径

#### ISSUE-006: simhash 重复实现
**描述**：`simhash` 算法在项目中存在 3 处重复实现。
**风险**：
- 维护成本增加
- 实现不一致导致结果差异
- 包体积增加
**修复建议**：
1. 提取公共 `simhash` 模块到 `backend/app/core/simhash.py`
2. 统一所有引用
3. 删除重复实现

#### ISSUE-007: `request.improved.ts` 废弃未启用
**描述**：`request.improved.ts` 文件存在但未被任何模块引用。
**风险**：
- 死代码误导开发者
- 包体积轻微增加
**修复建议**：确认无引用后删除。

#### ISSUE-008: `admin.ts` store 废弃
**描述**：`admin.ts` store 模块已废弃但代码仍存在。
**风险**：
- 死代码
- 包体积增加
**修复建议**：确认无引用后删除。

#### ISSUE-009: `graph_cypher/` 占位
**描述**：`graph_cypher/` 目录仅包含 1 行注释，模块未实现。
**风险**：
- 功能缺失
- 误导开发者认为模块已完成
**修复建议**：
1. 评估是否需要 Cypher 查询模块
2. 如需实现：补充完整实现
3. 如不需要：删除占位文件

#### ISSUE-010: npm audit 不可用
**描述**：当前 npm registry 不支持 `npm audit` 命令。
**风险**：
- 安全漏洞无法自动检测
**修复建议**：
1. 更换支持 audit 的 registry（如官方 registry）
2. 或使用 `snyk` 等替代工具
3. 定期手动审查依赖安全性
