# Phase 12-02: loop_results IDOR Complete Fix

**Phase:** 12 — 安全加固
**Wave:** 2
**Requirements:** SEC-04
**Depends on:** Wave 1 (12-01-PLAN) — needs auth context (get_current_user returning user["sub"]) to pass user_id into loop pipeline

## Goal

Add a `user_id` column to the `loop_results` table via Alembic migration 009, backfill existing rows with `user_id='system'`, pass the authenticated user's identity through the loop pipeline (from endpoint to orchestrator to DB record), and add ownership checks to the `loop_status` and `loop_history` endpoints so that regular users can only see their own runs while admin users retain full visibility.

Key design decisions:
- `nullable=True` with `server_default="system"` — allows the migration to add the column without NOT NULL constraint first, then backfill, then optionally alter to NOT NULL in a follow-up migration if desired
- `index=True` — supports efficient filtering by user_id in `get_loop_history`
- `String(255)` — matches the `LearningPlan.user_id` pattern (line 37 of learning_models.py)
- `server_default="system"` — existing rows get "system" as their user_id, making them visible to admin users but not regular users

### Task 4: Add IDOR guard to loop_status 404 response
**Type:** code
**Files:**
- `backend/app/api/v1/loop.py` — differentiate between "not found" and "not authorized"

**Details:**
When `get_loop_status` returns `None` for a run that exists but belongs to another user, the current code returns a generic 404. This is correct from a security perspective (don't leak information about resource existence), but we should ensure the audit log captures the authorization failure.

In the `loop_status` endpoint, add an audit log entry for the access attempt:
```python
@router.get("/status/{run_id}")
async def loop_status(
    run_id: str,
    session: Annotated[AsyncSession, Depends(get_db_session)],
    user: Annotated[dict[str, Any], Depends(get_current_user)],
) -> dict:
    status = await get_loop_status(
        run_id,
        session=session,
        user_id=user["sub"],
        is_admin=user.get("role") == "admin",
    )
    if status is None:
        # Could be "not found" or "not authorized" — log the attempt
        from app.utils.audit import AuditEntry, AuditEvent, audit_log
        audit_log(AuditEntry(
            event=AuditEvent.AUTHZ_DENIED,
            actor=user.get("sub", "unknown"),
            action=f"loop_status:{run_id}",
            detail="Loop run not found or not authorized",
            ip="",
        ))
        raise HTTPException(status_code=404, detail=f"Loop run '{run_id}' not found")
    return status
```

**Verification:**
- Accessing another user's loop run logs an `AUTHZ_DENIED` audit event
- The HTTP response is still 404 (no information leakage)

## Risk Assessment

| Risk | Severity | Mitigation |
|------|----------|------------|
| Migration 009 fails on existing data | Low | Column is nullable with server_default="system"; backfill UPDATE is idempotent |
| In-memory fallback bypasses IDOR | Low | In-memory fallback only used when no DB session (testing/fallback); production always uses DB |
| user_id='system' historical data visible to non-admin | Low | By design: historical data predates user association; only admin sees it. Acceptable. |
| Breaking change to orchestrator API | Medium | All new params have defaults; existing callers continue to work without changes |
| run_id UUID guessability | Low | UUIDs are hard to guess, but IDOR fix eliminates the attack vector entirely |
| Audit log for 404 may be noisy | Low | Only logs on explicit status check attempts; normal usage is not affected |
