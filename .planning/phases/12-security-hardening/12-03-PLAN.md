# Phase 12-03: ForeignKey Constraints + Settings Runtime Guard

**Phase:** 12 — 安全加固
**Wave:** 3
**Requirements:** SEC-05, SEC-06
**Depends on:** Wave 2 (12-02-PLAN) — migration 009 must be applied before migration 010 can be created; also depends on Wave 1 auth infrastructure for audit logging in SEC-06

## Goal

Add ForeignKey constraints to 6 UUID relationship fields across 4 models (with data cleanup for dangling references before adding constraints), and protect the Settings singleton from unrestricted runtime mutation by adding a `safe_update()` method with field whitelist + range validation, audit logging for PUT /pipeline/config, and Field constraints on PipelineConfigUpdateRequest.

### Task 2: Create Alembic migration 010 with FK constraints
**Type:** migration
**Files:**
- `backend/alembic/versions/010_add_foreign_key_constraints.py` — new migration file

**Details:**
Follow the existing migration pattern from `008_add_loop_results_table.py`:

```python
"""Add ForeignKey constraints to model relationship fields.

Revision ID: 010
Revises: 009
Create Date: 2026-07-12
"""
from collections.abc import Sequence

import sqlalchemy as sa

from alembic import op

revision: str = "010"
down_revision: str | None = "009"
branch_labels: str | Sequence[str] | None = None
depends_on: str | Sequence[str] | None = None


def upgrade() -> None:
    # ── Data cleanup: remove dangling references before adding FK ──

    # position_skill_relations.position_id → position_records.id
    op.execute(
        sa.text(
            "DELETE FROM position_skill_relations "
            "WHERE position_id NOT IN (SELECT id FROM position_records)"
        )
    )
    # position_skill_relations.skill_id → skill_records.id
    op.execute(
        sa.text(
            "DELETE FROM position_skill_relations "
            "WHERE skill_id NOT IN (SELECT id FROM skill_records)"
        )
    )
    # extraction_evaluation_records.extraction_id → jd_extraction_records.id (SET NULL)
    op.execute(
        sa.text(
            "UPDATE extraction_evaluation_records SET extraction_id = NULL "
            "WHERE extraction_id IS NOT NULL "
            "AND extraction_id NOT IN (SELECT id FROM jd_extraction_records)"
        )
    )
    # learning_progress.plan_id → learning_plans.id
    op.execute(
        sa.text(
            "DELETE FROM learning_progress "
            "WHERE plan_id NOT IN (SELECT id FROM learning_plans)"
        )
    )
    # evolution_changelog.snapshot_from_id → evolution_snapshots.id (SET NULL)
    op.execute(
        sa.text(
            "UPDATE evolution_changelog SET snapshot_from_id = NULL "
            "WHERE snapshot_from_id IS NOT NULL "
            "AND snapshot_from_id NOT IN (SELECT id FROM evolution_snapshots)"
        )
    )
    # evolution_changelog.snapshot_to_id → evolution_snapshots.id (SET NULL)
    op.execute(
        sa.text(
            "UPDATE evolution_changelog SET snapshot_to_id = NULL "
            "WHERE snapshot_to_id IS NOT NULL "
            "AND snapshot_to_id NOT IN (SELECT id FROM evolution_snapshots)"
        )
    )

    # ── Add FK constraints ──

    # PositionSkillRelation.position_id → PositionRecord.id (CASCADE)
    op.create_foreign_key(
        "fk_psr_position_id",
        "position_skill_relations",
        "position_records",
        ["position_id"],
        ["id"],
        ondelete="CASCADE",
    )
    # PositionSkillRelation.skill_id → SkillRecord.id (CASCADE)
    op.create_foreign_key(
        "fk_psr_skill_id",
        "position_skill_relations",
        "skill_records",
        ["skill_id"],
        ["id"],
        ondelete="CASCADE",
    )
    # ExtractionEvaluationRecord.extraction_id → JDExtractionRecord.id (SET NULL)
    op.create_foreign_key(
        "fk_eer_extraction_id",
        "extraction_evaluation_records",
        "jd_extraction_records",
        ["extraction_id"],
        ["id"],
        ondelete="SET NULL",
    )
    # LearningProgress.plan_id → LearningPlan.id (CASCADE)
    op.create_foreign_key(
        "fk_lp_plan_id",
        "learning_progress",
        "learning_plans",
        ["plan_id"],
        ["id"],
        ondelete="CASCADE",
    )
    # EvolutionChangelog.snapshot_from_id → EvolutionSnapshot.id (SET NULL)
    op.create_foreign_key(
        "fk_ec_snapshot_from_id",
        "evolution_changelog",
        "evolution_snapshots",
        ["snapshot_from_id"],
        ["id"],
        ondelete="SET NULL",
    )
    # EvolutionChangelog.snapshot_to_id → EvolutionSnapshot.id (SET NULL)
    op.create_foreign_key(
        "fk_ec_snapshot_to_id",
        "evolution_changelog",
        "evolution_snapshots",
        ["snapshot_to_id"],
        ["id"],
        ondelete="SET NULL",
    )


def downgrade() -> None:
    # Remove FK constraints (reverse order)
    op.drop_constraint("fk_ec_snapshot_to_id", "evolution_changelog", type_="foreignkey")
    op.drop_constraint("fk_ec_snapshot_from_id", "evolution_changelog", type_="foreignkey")
    op.drop_constraint("fk_lp_plan_id", "learning_progress", type_="foreignkey")
    op.drop_constraint("fk_eer_extraction_id", "extraction_evaluation_records", type_="foreignkey")
    op.drop_constraint("fk_psr_skill_id", "position_skill_relations", type_="foreignkey")
    op.drop_constraint("fk_psr_position_id", "position_skill_relations", type_="foreignkey")
```

**ON DELETE strategy rationale:**
- `CASCADE` for strong ownership: deleting a PositionRecord removes its PositionSkillRelation rows; deleting a LearningPlan removes its LearningProgress rows. This is correct because these child records have no meaning without their parent.
- `SET NULL` for nullable references: deleting a JDExtractionRecord nullifies ExtractionEvaluationRecord.extraction_id; deleting an EvolutionSnapshot nullifies the changelog's snapshot references. The child records retain independent value.

- `cd backend && poetry run alembic downgrade 009` rolls back without error
- After upgrade, `\d position_skill_relations` in psql shows FK constraints

### Task 4: Add safe_update() method to Settings
**Type:** code
**Files:**
- `backend/app/config.py` — add `safe_update()` method with field whitelist and validation

**Details:**
Add a `safe_update()` method to the `Settings` class that:
1. Only allows mutation of whitelisted fields
2. Validates values against the field's own Pydantic validators
3. Logs all changes via the audit system
4. Returns a dict of changed fields with old/new values

```python
from typing import Any, ClassVar

# Add to Settings class, after the pipeline config fields (around line 130):

# ── Runtime-mutable config whitelist (SEC-06) ──
_mutable_config_keys: ClassVar[set[str]] = {
    "pipeline_stage_timeout",
    "pipeline_worker_concurrency",
    "pipeline_crawl_concurrency",
    "pipeline_retry_max",
    "pipeline_retry_backoff",
}

def safe_update(self, updates: dict[str, Any], actor: str) -> dict[str, tuple[Any, Any]]:
    """Update mutable config fields with validation and audit logging.

    Args:
        updates: Dict of {field_name: new_value}. Only whitelisted fields are accepted.
        actor: Username of the user making the change (for audit log).

    Returns:
        Dict of {field_name: (old_value, new_value)} for changed fields.

    Raises:
        ValueError: If a field is not runtime-mutable or a value fails validation.
    """
    from app.utils.audit import AuditEntry, AuditEvent, audit_log

    changes: dict[str, tuple[Any, Any]] = {}
    for key, value in updates.items():
        if key not in self._mutable_config_keys:
            raise ValueError(
                f"Field '{key}' is not runtime-mutable. "
                f"Mutable fields: {sorted(self._mutable_config_keys)}"
            )
        if value is None:
            continue

        # Validate using the field's own constraints
        field_info = self.model_fields.get(key)
        if field_info is not None:
            # Run Pydantic field validator by attempting to set on a temp model
            # This catches constraint violations (ge, le, etc.)
            try:
                # Create a minimal validation by constructing a dict with just this field
                validated = type(self).model_validate({key: value, "app_env": self.app_env})
                # If validation passes, extract the validated value
                validated_value = getattr(validated, key)
            except Exception as e:
                raise ValueError(f"Invalid value for '{key}': {e}") from e
        else:
            validated_value = value

        old_value = getattr(self, key)
        if old_value != validated_value:
            object.__setattr__(self, key, validated_value)
            changes[key] = (old_value, validated_value)

    if changes:
        change_summary = "; ".join(
            f"{k}: {v[0]} -> {v[1]}" for k, v in changes.items()
        )
        audit_log(AuditEntry(
            event=AuditEvent.SENSITIVE_WRITE,
            actor=actor,
            action="update_pipeline_config",
            detail=change_summary,
            ip="",
        ))

    return changes
```

**Design notes:**
- `object.__setattr__` is used because Pydantic v2 models may be configured as frozen; this bypasses the frozen check while still being controlled through the whitelist
- The `ClassVar` annotation ensures `_mutable_config_keys` is not treated as a model field by Pydantic
- Validation is done by attempting to construct a temporary Settings instance with the new value, which runs all Pydantic field validators (including `ge`, `le` constraints)
- Only fields that actually change (old_value != new_value) are logged and returned

**Verification:**
- `settings.safe_update({"pipeline_stage_timeout": 3600}, actor="admin")` succeeds and returns `{"pipeline_stage_timeout": (1800, 3600)}`
- `settings.safe_update({"secret_key": "new_key"}, actor="admin")` raises `ValueError("Field 'secret_key' is not runtime-mutable")`
- `settings.safe_update({"pipeline_stage_timeout": -1}, actor="admin")` raises `ValueError` (fails validation)
- Audit log contains a `SENSITIVE_WRITE` entry for each successful update

```python
class PipelineConfigUpdateRequest(BaseModel):
    """Update pipeline configuration (SEC-06: all fields have range constraints)."""

    stage_timeout: int | None = Field(
        None,
        ge=60,
        le=7200,
        description="Stage timeout in seconds (60-7200)",
    )
    worker_concurrency: int | None = Field(
        None,
        ge=1,
        le=10,
        description="Worker concurrency (1-10)",
    )
    crawl_concurrency: int | None = Field(
        None,
        ge=1,
        le=20,
        description="Crawl concurrency (1-20)",
    )
    retry_max: int | None = Field(
        None,
        ge=0,
        le=10,
        description="Max retries (0-10)",
    )
    retry_backoff: int | None = Field(
        None,
        ge=1,
        le=300,
        description="Retry backoff base in seconds (1-300)",
    )
```

**Range constraint rationale:**
- `stage_timeout: 60-7200` — minimum 1 minute, maximum 2 hours. Prevents instant timeout (0) and excessively long waits.
- `worker_concurrency: 1-10` — prevents resource exhaustion from too many concurrent workers.
- `crawl_concurrency: 1-20` — crawl is I/O-bound, allows higher concurrency but still bounded.
- `retry_max: 0-10` — 0 means no retries, 10 is generous upper bound.
- `retry_backoff: 1-300` — minimum 1 second, maximum 5 minutes base. Prevents negative or zero backoff.

```python
async def update_pipeline_config(
    body: PipelineConfigUpdateRequest,
    user: Annotated[dict[str, Any], Depends(require_admin)],  # NEW: inject user for audit
) -> PipelineConfigResponse:
    """更新流水线配置（通过 safe_update 防护，不直接修改 settings 单例）。"""
```

## Risk Assessment

| Risk | Severity | Mitigation |
|------|----------|------------|
| Dangling references block FK constraint creation | High | Migration 010 includes cleanup SQL that runs before FK creation. Test on staging first. |
| CASCADE delete removes more data than expected | Medium | CASCADE only affects child records with no independent value (position_skill_relations, learning_progress). SET NULL preserves child records for nullable references. |
| safe_update validation too strict | Low | Validation uses the same Pydantic field constraints already defined in Settings. If a value is valid at startup, it's valid at runtime. |
| safe_update performance (temp model construction) | Low | Only called on admin config updates (rare operation). Temp model construction is fast. |
| PipelineConfigUpdateRequest constraints break existing clients | Low | Current clients likely send reasonable values. The constraints are generous (e.g., stage_timeout 60-7200). |
| String-based soft references accidentally get FK | None | Explicitly excluded in Task 3. No FK for name-based references. |
| Migration 010 rollback loses FK constraints but not data | Low | Downgrade only drops FK constraints; no data is deleted. Dangling references may reappear after downgrade. |
