# Phase 8-01: 修复 Vitest 覆盖率配置 + 页面测试基础（Tracer）

## Goal

修复 vitest 覆盖率配置使其正确统计源码覆盖，建立页面级测试基础框架，并为 1 个页面编写完整的冒烟测试作为 tracer。

## Success Criteria

1. Vitest `coverage.include` 从 `src/**/__tests__/**/*.test.ts` 改为 `src/**/*.ts` + `src/**/*.vue`
2. `coverage.exclude` 正确排除 `node_modules`, `dist`, 测试文件自身
3. 覆盖率报告显示源码（.ts / .vue）的实际覆盖率，而非仅测试文件自身的覆盖率
4. 覆盖率阈值从 60% 下调到合理预期（首次运行确认实际值后调整，预期 15-30%）
5. 页面测试基础设施就绪：`tests/` 目录结构、测试辅助函数、setup 文件
6. 一个页面（如 `Home.vue`）的完整冒烟测试通过（渲染 + 基本交互）
7. 所有现有 232 个测试保持通过

## Tasks

### 1.1 修复 Vitest 覆盖率配置

**文件:** `frontend/vitest.config.ts`

```ts
// 修改 coverage.include:
coverage: {
  provider: 'v8',
  reporter: ['text', 'json', 'html'],
  include: ['src/**/*.ts', 'src/**/*.vue'],
  exclude: [
    'node_modules',
    'dist',
    'src/**/*.d.ts',
    'src/**/__tests__/**',
    'src/**/*.test.ts',
    'src/**/*.spec.ts',
    'src/main.ts',  // 入口文件不需要测试
    'src/env.d.ts',
  ],
  thresholds: {
    lines: 20,      // 从 60% 下调，首次运行后调整
    functions: 15,
    branches: 10,
    statements: 20,
  },
},
```

**验证:** `npx vitest run --coverage` 报告应显示源码 `.ts` / `.vue` 文件的覆盖率，而非仅测试文件。

### 1.2 建立页面测试基础设施

**目录结构:**
```
frontend/src/pages/__tests__/
  └── setup.ts                  # 测试 setup (Element Plus mock, router mock, Pinia)
  └── helpers.ts                # 页面渲染辅助函数
  └── Home.spec.ts              # tracer 页面测试
```

**`setup.ts` 内容:**
- 配置 jsdom 环境
- 导入 Element Plus 组件注册（`global.plugins` 注入）
- **Pinia 配置:** 使用 `setActivePinia(createPinia())` 模式（与现有 26 个测试文件一致），**不**需要 `@pinia/testing`
- **Router 配置:** 使用 `global.stubs` 策略：
  - `global.stubs['router-link']` = `true`（桩组件）
  - `global.stubs['router-view']` = `true`
  - 需要 `useRoute`/`useRouter` 的页面，使用 `vi.mock('vue-router', () => ({ useRoute: ..., useRouter: ... }))`
- 提供 `@/composables/useAuthBootstrap` mock（`vi.mock('@/composables/useAuthBootstrap')`）

**`helpers.ts` 内容:**
```typescript
// renderPage: 统一渲染函数，注入 Element Plus + 可选 Pinia + Router stubs
import { mount } from '@vue/test-utils'
import ElementPlus from 'element-plus'

export function renderPage(component: any, options?: { pinia?: any; stubs?: Record<string, any> }) {
  return mount(component, {
    global: {
      plugins: [ElementPlus],
      stubs: {
        'router-link': true,
        'router-view': true,
        ...options?.stubs,
      },
    },
  })
}
```
- `mountWithSetup(component)` — 适用于需要手动控制 mount 选项的场景

### 1.3 编写 Home.vue 冒烟测试（Tracer）

**文件:** `frontend/src/pages/__tests__/Home.spec.ts`

**注意:** Home.vue 包含 Graph2D（@antv/G6）、Graph3D（three.js）和 ECharts 组件，这些在 jsdom 中无法渲染 Canvas/WebGL。
- 使用 `shallowMount` 或 `global.stubs` 将图形组件替换为桩组件
- 具体 stubs: `{ 'graph-2d': true, 'graph-3d': true, 'v-chart': true }` 或按组件名匹配
- 测试聚焦于页面结构（标题、加载/空/错误状态）而非图形渲染

**测试内容:**
1. 页面渲染 — 验证标题文本存在
2. 图谱容器 — 验证图谱组件的桩组件或容器 div 渲染
3. 加载状态 — 模拟 graph store loading=true，验证加载指示器
4. 空数据状态 — 模拟空 domains，验证空状态提示
5. 错误状态 — 模拟 API 错误，验证错误提示
