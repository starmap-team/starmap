<objective>
消除 Docker Compose 生产配置中的安全风险，加固 CORS 生产校验，确保开发环境 Redis 有默认密码保护。

Purpose:
- 生产环境 `NO_PROXY=*` 会绕过所有代理设置，使依赖代理进行安全监控或出口控制的环境完全失效（严重性：高）
- 开发环境 Redis 无密码保护，若开发网络可访问则存在被利用风险（严重性：中）
- 生产 CORS 校验当前仅检查"是否全为 dev origins"，混合配置可能漏过（严重性：中）

- docker-compose.dev.yml 中 Redis 容器添加 --requirepass
- backend/app/config.py 中 CORS 生产校验从"全为 dev→报错"升级为"含任何 dev→报错"
</objective>

  <name>Task 1: Remove NO_PROXY=* from production Docker Compose and add Redis password to dev compose</name>
  <files>docker-compose.prod.yml, docker-compose.dev.yml</files>
  <action>
    Per D-02 (INFRA-02): Two changes to Docker Compose security configuration.

    **1. docker-compose.prod.yml — Remove NO_PROXY=* from x-common-env:**

    The `x-common-env` anchor (lines 9-11) defines `NO_PROXY: "*"` and `no_proxy: "*"` that are included in `backend` and `celery-worker` services via `<<: *common-env`. These lines MUST be removed because:
    - `NO_PROXY=*` disables ALL proxy traffic, bypassing security monitoring and egress control
    - The production compose should not assume no proxy is needed — each deployment must explicitly configure proxy settings

    Delete the two lines from the `x-common-env` block. Then remove the `<<: *common-env` reference from `backend` (line 27) and `celery-worker` (line 81) services since the anchor will be empty. If the `x-common-env` anchor becomes empty after removal, delete the entire anchor definition.

    The `ollama` service (line 323-324) has its own `NO_PROXY=*` — this is intentional for Ollama's local-only model access and should remain.

    **2. docker-compose.dev.yml — Add Redis password:**

    The Redis service (lines 162-172) currently has no `command` entry and no `--requirepass` flag. Add a `command` field that starts Redis with a password requirement:

    ```yaml
    command: redis-server --requirepass ${REDIS_PASSWORD:-starmap_dev_redis} --maxmemory 256mb --maxmemory-policy allkeys-lru
    ```

    This mirrors the production pattern but with a dev-specific default password `starmap_dev_redis`. The password is overridable via `REDIS_PASSWORD` env var.

    Note: The `.env.example` update for `REDIS_PASSWORD` is handled by Plan 1 (Task 3). After this change, developers must ensure their `.env` has `REDIS_PASSWORD` set or the default `starmap_dev_redis` will be used.
  </action>

<task type="auto">
  <name>Task 2: Stricter CORS production validation — reject any dev-only origin</name>
  <files>backend/app/config.py</files>
  <action>
    Per D-03 (INFRA-03): Strengthen the production CORS origin validation in `backend/app/config.py` (around lines 375-391).

    The current check (line 387) uses `set(self.cors_origins).issubset(_dev_only_origins)` — this only catches the case where ALL origins are dev-only. If someone configures a mix like `http://localhost:5173,https://myapp.com`, the check passes silently because the set is NOT a subset of dev-only origins.

    Replace the block with a per-origin check:

    ```python
    if self.app_env == "production":
        _dev_only_origins = {
            "http://localhost:5173",
            "http://127.0.0.1:5173",
            "http://localhost:5176",
            "http://127.0.0.1:5176",
            "http://localhost:5174",
            "http://localhost:5175",
        }
        _found_dev_origins = [o for o in self.cors_origins if o in _dev_only_origins]
        if _found_dev_origins:
            raise RuntimeError(
                f"CORS_ALLOWED_ORIGINS 包含开发环境专有 origin: {_found_dev_origins}。"
                f"生产环境必须通过 CORS_ALLOWED_ORIGINS 环境变量移除所有 dev localhost 值。"
                f"如需添加生产域名，请设置 CORS_ALLOWED_ORIGINS=https://yourdomain.com,https://api.yourdomain.com"
            )
    ```

    This change:
    - Rejects ANY origin that is a dev-only localhost origin, not just when ALL origins are dev-only
    - Provides a clear error message listing which origins are problematic
    - Includes a hint on how to set the correct production value

    Keep the existing `_dev_only_origins` set unchanged. The surrounding code (production SECRET_KEY check, Redis password check, etc.) must remain untouched.
  </action>
