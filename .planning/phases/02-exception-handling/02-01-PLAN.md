    Per ARCH-02: Replace 15+ bare `except Exception` in executor.py with specific exception types and add `logger.exception()`.

    Pattern to follow for each replacement:
    ```python
    # BEFORE:
    except Exception as exc:
        logger.error("...: {}", exc)
        raise

    # AFTER:
    except SpecificError as exc:
        logger.exception("...: {}", exc)
        raise
    except AnotherSpecificError as exc:
        logger.exception("...: {}", exc)
        raise
    ```

    Key replacements in executor.py (approximate line numbers based on research):
    - Line 116: `except Exception as exc` → catch `HTTPError`, `ConnectionError`, `TimeoutError` etc. for crawl dispatch
    - Line 259: `except Exception as exc` → catch `PipelineStageError` for stage execution
    - Line 305: `except Exception as exc` → catch `PipelineStageError` for dedup stage
    - Line 416: `except Exception as exc` → catch `PipelineStageError` for import stage
    - Line 428: `except Exception as exc` → catch `PipelineStageError`
    - Line 496: `except Exception as exc` → catch `PipelineStageError`
    - Lines 575, 587, 597: `except Exception as exc` → catch `PipelineStageError` or `PipelineTimeoutError`
    - Lines 626, 646, 652, 675, 823, 843, 882: `except Exception as exc` → catch specific Neo4j/DB errors or `PipelineStageError`

    For truly unexpected errors (where the operation genuinely cannot anticipate all failure modes), use the pattern:
    ```python
    except StarMapError:
        raise  # Re-raise domain exceptions already handled
    except Exception as exc:
        logger.exception("Unexpected error in {operation}: {}", exc)
        raise PipelineStageError(str(exc), stage="stage_name") from exc
    ```

    This approach ensures:
    - Known domain errors propagate as domain exceptions
    - Unknown errors are wrapped in a domain exception with full traceback
    - No bare `except Exception` remains that silently swallows errors
