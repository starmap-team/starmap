## Phase 1: 修复权限漏洞与API不一致（P0）

### 1.1 统一数据源API（后端）

**问题**：`admin.py` 中的 `/admin/sources` 未被前端使用，前端调用的是 `/datasources`。

**修复方案**：
- 移除 `admin.py` 中未使用的 `get_sources()` 端点
- 在 `datasource.py` 中为敏感操作添加 `require_admin` 保护
- 更新 OpenAPI 契约

**修改文件**：
- `backend/app/api/v1/admin.py` — 移除 `get_sources()` 和 `SourceConfig`/`SourceListResponse`
- `backend/app/api/v1/datasource.py` — 为 `PUT`/`POST` 端点添加 `require_admin`
- `starmap-contracts/openapi.yaml` — 同步移除 `/admin/sources`

### 1.2 修复数据源管理权限（后端）

**问题**：`datasource.py` 的更新和同步端点缺少 admin 保护。

**修复方案**：
```python
# datasource.py 中新增 admin router
from app.dependencies import require_admin

# 将敏感操作移到 admin 保护的子路由
admin_datasource_router = APIRouter(dependencies=[Depends(require_admin)])
admin_datasource_router.put("/{source_id}", ...)
admin_datasource_router.post("/{source_id}/sync", ...)
```

**修改文件**：
- `backend/app/api/v1/datasource.py` — 拆分普通查询和敏感操作路由
- `backend/app/api/v1/router.py` — 注册 admin 保护的 datasource 子路由

### 1.3 修复路由依赖注入重复（后端）

**问题**：`api_router` 已设置 `get_current_user`，`admin.router` 又叠加 `require_admin`（内部也依赖 `get_current_user`）。

**修复方案**：保持现状（不影响功能），添加注释说明依赖层级关系。

**修改文件**：
- `backend/app/api/v1/router.py` — 添加注释说明依赖层级

```python
        skill = SkillRecord(name=row.entity_name, ...)
        session.add(skill)
    elif row.entity_type == "position":
        # 创建或更新 PositionRecord
        ...
    await session.commit()
```

## Phase 3: 完善错误处理与前后端一致性（P1）

### 3.1 修复后端"静默失败"模式（后端）

**问题**：多个端点使用裸 `except Exception` 返回空结果。

**修复方案**：
```python
# 修复前
try:
    result = await session.execute(...)
except Exception:
    return SourceListResponse(items=[])  # 静默失败

# 修复后
try:
    result = await session.execute(...)
except SQLAlchemyError as exc:
    logger.error("Database error: {}", exc)
    raise HTTPException(status_code=500, detail="Database query failed")
```

**修改文件**：
- `backend/app/api/v1/admin.py` — `get_sources()`, `get_review_queue()`
- `backend/app/api/v1/admin_graph_nodes.py` — `list_graph_nodes()`

### 3.2 修复前端错误吞没（前端）

**问题**：`datasource.ts` 中多个方法使用裸 `catch` 吞没错误。

**修复方案**：
```typescript
// 修复前
} catch {
    graphNodes.value = []
}

// 修复后
} catch (e: unknown) {
    error.value = e instanceof Error ? e.message : '请求失败'
    console.error('[Admin] Failed to fetch graph nodes:', e)
    throw e // 让上层组件处理
}
```

**修改文件**：
- `frontend/src/stores/datasource.ts` — 所有 catch 块
- `frontend/src/composables/useGraphNodeEditor.ts` — 错误处理

### 3.3 修复审核操作错误处理（前端）

**问题**：`ReviewQueuePanel.vue` 中审核操作失败仍显示成功消息。

**修复方案**：
```typescript
async function handleApprove(id: number) {
    try {
        await admin.approveAudit(id)
        ElMessage.success('已批准')
    } catch (e: unknown) {
        ElMessage.error('审核失败: ' + (e instanceof Error ? e.message : '未知错误'))
        throw e
    }
}
```

**修改文件**：
- `frontend/src/components/ReviewQueuePanel.vue` — `handleApprove()`, `handleReject()`

**问题**：`_ab_results` 存储在进程内存中，重启后丢失。

**修复方案**：使用 Redis 存储 A/B 测试结果。

```python

async def record_ab_result(name: str, req: ABResultRequest, redis: Redis = Depends(get_redis_client)):
    entry = {...}
    # 使用 Redis List 存储，限制长度
    await redis.lpush(f"ab:results:{name}", json.dumps(entry))
    await redis.ltrim(f"ab:results:{name}", 0, _MAX_RESULTS_PER_PROMPT - 1)
```

## Phase 6: 前端权限控制与操作审计（P2）

### 6.1 添加用户角色信息存储（前端）

**问题**：前端没有用户角色信息，无法区分 admin/普通用户。

**修复方案**：
```typescript
// stores/user.ts
export const useUserStore = defineStore('user', () => {
    const user = ref<{ sub: string; role: string; username: string } | null>(null)
    const isAdmin = computed(() => user.value?.role === 'admin')
    
    async function fetchUser() {
        const data = await request.get('/auth/me')
        user.value = data
    }
    
    return { user, isAdmin, fetchUser }
})
```

**修改文件**：
- 新增 `frontend/src/stores/user.ts`
- `frontend/src/api/request.ts` — 添加 token 解码获取用户信息

## 📊 风险与依赖

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Alembic 迁移失败 | 数据库模型变更 | 先在开发环境测试迁移脚本 |
